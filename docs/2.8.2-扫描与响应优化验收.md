# ObManage 2.8.2 扫描与响应优化验收

开始时 `main` 与 `origin/main` 指向 2.8.1 的 `678b112ee1322330e545d6d2c691fb393fa8786f`。已跟踪文件干净，保留已有未跟踪的任务书目录。基准从该 SHA 独立提取 Python 模块，使用同一合成数据和独立 SQLite 状态。最终版为 2.8.2。

环境为 Windows 11 10.0.26200、Python 3.14.2、Intel Core i7-14700KF。Windows 存储查询确认系统临时卷为本机 NVMe SSD、NTFS 固定卷。各组轮换运行，系统缓存未控制。诊断计数及内存跟踪与墙钟测量分开。所有仓库、登记文件和状态目录均为合成数据。

## 统计线程池实验

[实验脚本](../tools/benchmark_scan_experiments.py)只在独立加载的旧模块中替换池的生命周期，保留目录分组、逐文件核验、线程上下文、顺序汇总和有界排队。各配置逐字段等价，轮换五次计时，另做计数和内存跟踪。

| 样本 | 仓库数 / 笔记数 / 单文件 | 按仓库最多 4 线程 | 共享 1 | 共享 2 | 共享 4 |
| --- | --- | ---: | ---: | ---: | ---: |
| 小文件约 1k | 24 / 960 / 960 B | 0.673 s | 0.734 s | 0.687 s | 0.665 s |
| 小文件约 10k | 24 / 9,600 / 960 B | 5.519 s | 6.251 s | 5.718 s | 5.508 s |
| 大文件 | 12 / 144 / 192 KiB | 0.183 s | 0.190 s | 0.178 s | 0.180 s |

两组小文件各建 24 个池，诊断轮记录 96 个不同 worker 线程 ID。共享方案建一个池，使用 1、2、4 个 worker。约 10k 组的构造函数累计约 0.28 毫秒，实际线程在提交后启动。共享 4 线程的墙钟只缩短 0.2%，共享 2 线程在大文件组略快、两组小文件较慢。正式版保留按仓库建池。关闭字符统计、无 Markdown 或无仓库时均无读取池。取消到达后，待处理文件在打开前停止。

约 10k 组单轮 Python 分配峰值按仓库为 8.07 MiB，共享 1、2、4 线程为 8.15、8.15、8.16 MiB。

`artifacts/scan-282-pools.json` 有各轮耗时、创建次数、线程使用、等待与执行累计、Python 内存样本。多线程累计时间可重叠。专项覆盖跨块解码、无效 UTF-8、读取故障、排队取消、句柄和线程回收、连续任务及单调进度。

## 仓库选择器历史结果

[应用窗口](../obmanage/ui.py)在镜像、增量、备份、统计、`.comSync`、`.Trash` 和 `.Archive` 的同类选择控件间共享最多 8 个范围的展示记录。键区分规范化集合根、登记文件来源、发现方式和转换规则，`.comSync` 来源列表的创建时间转换单独分区。“当前运行”每次查实际窗口。记录只包含完整成功的展示行及身份，进程退出即释放。

命中时先显示“上次扫描结果 · 正在实时刷新”，可以搜索及点选。旧结果要等本轮后台发现完成，且路径、集合根、登记来源、仓库目录和普通 `.obsidian` 身份匹配才填入。设备号和文件标识来自实时文件系统快照。更新后保留通过核验的选中行及搜索词；身份变化时要求重新选择。取消、失败和部分结果会显示状态，保留最后一次完整记录供下次打开时使用。

应用开始可能写入的任务时清空历史；事务记录修订或可读状态变化也会清空。外部变化由下次实时读取发现。只有本轮发现的集合进入 `catalog_ready`。镜像/备份分析、增量结束及执行前双端预检、`.comSync` 部署预览、`.Trash` 独立根级清单和 ZIP 来源复核分别从自己的服务入口实时运行。

刷新发现历史范围或身份失效时会撤销该页旧预览和确认。路径成功填入后，页面按已有输入变化规则处理。

最终源码在 Windows 原生 Qt 用 25 仓库、每端 1,100 文件的夹具交替五轮。分别记录表格有效行首次绘制和本轮实时结果就绪。

最终 10 次命中均绘制了历史行，实时就绪增加约 38–65 毫秒。较早的同口径五轮，跨页首次可见为 253 → 36 毫秒，实时就绪为 234 → 244 毫秒。两组绝对时间随本机负载波动，首次可见的相对改善一致。最终原始事件和 GUI 定时器采样见 `artifacts/scan-282-picker-release.json`，较早的表格绘制数据见 `artifacts/scan-282-picker-final.json`。

## 聚合诊断和内存

[ScanMetrics](../obmanage/scanning/metrics.py)沿用默认关闭、显式采样或 DEBUG 时收集的方式。增量分别计初次采集、发现、内容哈希、SQLite 打开/读写和末次复核。统计计每仓库目录清单、读取阶段墙钟及 worker 累计读时，并记录建池和线程启动次数。选择器分别计有效行绘制和实时就绪。管理任务记录可取消状态和从第一次请求取消到停止工作的时间。旧版本缺少的阶段在对照记录中留空。

最慢的 5 个仓库只保留任务内序号、墙钟、文件/目录/逻辑字节数和该阶段的完整性。增量样本为两端配对比较，统计样本为逐仓库读取和复核。末次全局异常仍以任务状态报告。计数无正文、路径或盘符。`scandir`、`stat`、`lstat`、`DirEntry.stat` 是 Python 请求，父子阶段可嵌套，worker 计时可能重叠。

同一 1,100 文件组的一轮内存测量见 `artifacts/scan-282-final-memory.json`。Python 峰值的前后样本为首次增量 8.21 → 7.33 MiB、纯元数据统计 1.15 → 1.16 MiB、严格 UTF-8 统计 1.21 → 1.22 MiB。该次进程生命周期工作集峰值为 62.6 MiB，不能分配到各任务。样本为内存量级观察。

## 复现与设备边界

在项目根目录运行，输出选择新文件名。默认用系统临时卷。

```powershell
.\.venv\Scripts\python.exe tools\benchmark_scanning.py --vaults 24 --files 40 --repeats 5 --timing-only --output artifacts\scan-282-repeat.json
.\.venv\Scripts\python.exe tools\benchmark_scanning.py --vaults 24 --files 400 --repeats 3 --scenarios statistics_metadata statistics_utf8 --timing-only --output artifacts\scan-282-10k-repeat.json
.\.venv\Scripts\python.exe tools\benchmark_scan_experiments.py pools --repeats 5 --output artifacts\scan-282-pool-repeat.json
.\.venv\Scripts\python.exe tools\benchmark_scan_experiments.py manifests --repeats 3 --output artifacts\scan-282-manifest-repeat.json
.\.venv\Scripts\python.exe tools\benchmark_catalog_picker.py --repeats 5 --output artifacts\scan-282-picker-repeat.json
```

外接卷须明确准备专用测试目录。工具拒绝盘根、仓库及其后代、链接、事务或已有基准标记。数据放在随机独占子目录。清理前重查父子目录身份及运行标记，校验失败会停止并给出待检查位置。移动侧和统计在指定卷运行，本机侧和状态库留在系统临时卷。

```powershell
.\.venv\Scripts\python.exe tools\benchmark_scanning.py --test-parent "X:\ObManageBenchmarkSandbox" --vaults 24 --files 40 --repeats 5 --timing-only --output artifacts\scan-282-usb-timing.json
```

本机 NTFS SSD 已实测。物理 USB NTFS、USB exFAT、移动机械盘、真实热拔插、长时间阻塞 I/O 和断电未测。卷替换故障用隔离目录注入。Windows 文件系统与固定/可移动类别可自动读取，设备总线需要单独确认。Python 分配峰值来自 `tracemalloc`，Windows 工作集是进程生命周期峰值。

## 回归与发布验证

- Windows 最终源码执行 `.\.venv\Scripts\python.exe -m pytest -q --tb=short`，750 通过、0 失败、0 跳过，耗时 497.85 秒。包含目录联接、标记和目录替换、部分刷新、待处理点选、预览失效、资源回收、双方向镜像、视频保护、独立基线、部署事务、根级回收站和 ZIP 回归。
