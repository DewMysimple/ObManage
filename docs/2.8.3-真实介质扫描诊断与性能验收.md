# ObManage 2.8.3 真实介质扫描诊断与性能验收

## 环境与基线

起始分支为 `main`，基线是 2.8.2 的 `f1c34ddc01b421ab4fe905af724e932a62df1a10`。当时已跟踪文件干净，保留已有的未跟踪任务书。对照通过 `git archive` 提取该提交的 Python 模块，独立加载到新建的临时目录。墙钟轮不启用计数或内存跟踪，同一场景按旧、新、新、旧、旧、新执行。

Windows 11 构建 26200，Python 3.14.2，Intel Core i7-14700KF。Windows 卷和磁盘查询确认本机端 `LOCAL_VAULT` 为 NVMe/NTFS，系统报告 SSD。移动端 `PORTABLE_VAULT` 为 USB/exFAT，系统没有识别 HDD 或 SSD，介质类型记为 `unknown`。两个卷都由系统报告为固定卷，不能据此推断连接总线。另一次只读健康查询报告两设备健康，温度均为 37 °C，未持续测温。系统临时目录位于 NVMe/NTFS。四个 Obsidian 进程保持运行，未控制应用活动或系统缓存。输入前后元数据变化、卷或目录身份失效、业务结果有读取问题或新旧输出不同的样本作废。

两端都是仓库集合，集合根无直接标记，均发现 47 个仓库，其中一个嵌套。首个有效基线的各端业务统计覆盖 24,683 个文件、11,490 篇 Markdown、42,058,599,227 字节。普通目录数分别为 3,674 和 3,673。按各端自身同路径比较，聚合计数相同也不能判定文件等价。实盘只执行只读场景，合成夹具只在系统临时卷创建。

## 本机复现

从源码工作区使用已安装依赖的 Python。先为两个变量填入现有集合路径。把输出设在系统临时目录的已有普通目录，使用新文件名。`--counts` 或 `--memory` 另起一轮，并修改报告文件名。实际设备不可用或保护区不明时工具退出并给出诊断。Windows 可能在只读访问时维护最后访问时间。

```powershell
$report = Join-Path ([Environment]::GetFolderPath('LocalApplicationData')) `
  "Temp/obmanage-283-$([DateTime]::Now.ToString('yyyyMMdd-HHmmss')).json"
.\.venv\Scripts\python.exe -B tools/benchmark_real_readonly.py `
  --local-vault $LOCAL_VAULT --portable-vault $PORTABLE_VAULT `
  --mode discovery metadata picker --repeats 3 `
  --acknowledge-read-only-real-data --output $report
```

`strict-utf8` 读取 Markdown 正文并保留严格解码状态。`incremental-preview` 只调用 `analyze`，每版每轮使用新 SQLite。空基线即使在快速模式也可能读大量内容，因此要显式加 `--include-full-hash`。额外加 `--deep` 运行完整内容校验。两种模式均不执行同步。

工具先检查两个范围和输出目录的真实路径、祖先、卷与目录身份，再复用仓库发现验证有效标记。保护区全树只读检查覆盖业务会排除的子树。遇到无法确定边界的重解析目标时退出。状态、参考源码与报告只在已验证的 Windows 系统卷临时目录创建，写入期间固定普通目录句柄。报告独占创建，旧文件保留。两个版本的结果及输入元数据摘要都只在内存比较，JSON 只记录等价布尔值与匿名聚合。最终工具按各场景的观察范围单独判断元数据漂移，并保留全程漂移标志。开发工具固定本轮已审计的 2.8.2 引用。

合成基准的统计大组把 `--files` 改为 `400` 并指定 `--scenarios statistics_metadata statistics_utf8`。单独计数时去掉 `--timing-only`，用 `--memory` 可测 Python 分配与进程工作集。每次选择新报告文件名，测试数据由运行标记保护的系统临时目录创建。

```powershell
.\.venv\Scripts\python.exe -B tools/benchmark_scanning.py `
  --baseline-ref f1c34ddc01b421ab4fe905af724e932a62df1a10 `
  --vaults 24 --files 40 --repeats 3 --timing-only `
  --output artifacts/scan-283-local-replay.json
```

## 安全与交付验证

[只读工具测试](../tests/test_benchmark_real_readonly.py)拦截文件打开、删除、重命名、替换、目录创建和递归复制等修改路径，验证增量 SQLite 仅在独立状态中创建。覆盖上下级和大小写别名、目录联接、外部重解析目标、卷身份变化、不可用 Windows API、缺少 Qt、标记缺失、输出冲突、未审计引用、匿名报告和场景级漂移判定。[路径测试](../tests/test_paths.py)覆盖祖先实时属性、失败回退、目录联接替换和长中文路径。末次新增、改名、读写异常、快速与完整内容校验、严格 UTF-8、嵌套去重、取消和八页工作流由现有回归和本轮对照共同覆盖。

Windows 全量 `pytest -q --tb=short` 为 781 项通过，零失败、零跳过，耗时 232.72 秒。工程记忆索引、66 页记忆检查、相对链接和 Git 差异格式检查通过。暂存内容经过隐私审查，原始报告、真实路径、用户任务书和构建产物留在本机。

最终工具在真实两端各做一轮功能检查，发现、历史首帧、待核验点选和实时接受均通过。该轮与发布验证同机运行，仅作功能证据。源码窗口检查八页的普通、小和最大化尺寸，选择器另查全屏，30 张隔离演示记录通过。便携 ZIP 含 236 个条目，大小 51,022,721 字节，通过 CRC、平铺根层和指南一致性检查。解压后的 EXE 在八页分别启动并正常退出，隔离 `--preview --deep` 成功，夹具内容保持原样。
