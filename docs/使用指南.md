# ObManage 使用指南

ObManage 用六个独立页面管理一组本地 Obsidian 仓库。左侧选择功能；右侧完成范围选择、只读分析、目标勾选和执行确认。程序同时只运行一个任务，切换页面不会让两个任务并发修改仓库。

## 共同原则

- “仓库集合根目录”可以包含多个子仓库。只有真实、可读取的普通 `.obsidian` 目录才构成仓库标记。
- 来源始终只读；部署和镜像只写页面明确显示的目标。
- 分析或统计可取消。任何输入、方向、组件或目标选择改变后，都要重新分析并重新确认。
- 路径列可选择、复制，完整值也会显示在悬停提示中。
- 链接、目录联接、其他重解析点、特殊文件、大小写歧义路径和越界路径会被拒绝，不会跟随到仓库外。
- 操作失败时先查看页面状态和“操作日志”。不要手工删除带有 `.obmanage-` 前缀的待处理事务目录。
- 左侧出现“待恢复事务”时，先进入对应页面撤销、恢复或确认；处理完成前新的镜像、部署、清理和定时镜像都会暂停。

## 1. 仓库镜像

镜像页固定显示“本机仓库”和“移动硬盘仓库”。“带到移动硬盘”以本机为来源，“带回本机”以移动硬盘为来源。所选文件夹就是镜像根目录，不会自动多套一层。

1. 核对两个位置与方向。
2. 点击“分析差异”。分析读取两边，并把已完成的内容校验记录写入本机应用状态目录。
3. 查看新增、更新、删除和跳过；“实际修改位置”全部位于本轮目标。
4. 勾选方向确认，点击“更新本机”或“更新移动硬盘”。

每轮以来源为准，目标独有内容会删除；两边各自修改时，程序不会合并冲突，也不会自动选择时间较新的版本。普通复制先写目标盘临时文件并校验，新增与更新成功后才进入删除阶段。来源完全为空而目标有内容时，需要额外确认。

“完整内容校验”会重新读取两端全部普通文件并计算 SHA-256。两端位于不同卷时会并行读取；它仍是全量校验，速度取决于较慢磁盘。取消后已完成的常规校验记录可以继续复用。

### 定时与托盘

定时默认关闭，可选择间隔或每日时间。开启即代表授权当前绑定方向自动镜像，包括删除。

- 切换方向或修改任一镜像路径会暂停定时。
- 忙碌时到点会跳过本轮，不累计补跑。
- 有待恢复部署或隔离批次时到点也会跳过，避免新写入破坏撤销依据。
- 磁盘未连接会记录原因，下次到点重新检查。
- 空来源可能清空目标时，定时会暂停并要求手动处理。
- 关闭窗口时，如有后台任务或定时已启用，程序进入托盘；托盘中的“退出”才会安全停止后台任务并结束程序。

## 2. 仓库统计

统计页全程只读。

1. 选择仓库集合根目录。
2. 选择是否读取 Markdown 内容并统计 UTF-8 解码后的 Unicode 字符，以及是否包含仓库根级 `.trash`。
3. 点击“开始统计”。

默认排除 `.obsidian`、根级 `.trash` 和已经单独识别的嵌套子仓库，避免重复计数；根级 `.trash` 里残留的 `.obsidian` 也不会被当成活动仓库或分发目标。关闭字符统计后只读取元数据，适合快速查看仓库和笔记规模。无法读取、无效 UTF-8、同大小同时间戳变化或扫描期间晚出现的目录项会形成可见警告，并把对应结果标为“部分统计”，不会静默当作精确结果。

## 3. 模板套件部署

模板套件页用于从一个套件来源部署 `.claude`、`.claudian`、`.obsidian` 和 `File` 中明确选中的组件。

1. 选择仓库集合根目录与模板套件来源。
2. 勾选要部署的组件。
3. 扫描仓库，逐项勾选目标；来源仓库不会成为目标。
4. 分析文件与目录差异，重点核对删除数量和实际目标路径。
5. 勾选执行确认并部署。

每个选中组件都是完整子树：目标中的同名子树最终与来源一致，目标独有文件会出现在删除预览中。没有勾选的组件不读取也不修改。

## 4. Obsidian 配置分发

配置分发页接受仓库目录或 `.obsidian` 目录作为来源，把解析出的 `.obsidian` 完整分发到明确选择的其他仓库。

完整分发会包含插件、主题、工作区等来源目录中的普通文件；目标 `.obsidian` 独有内容属于删除范围。若某些设置只适合一台电脑，请先在来源中整理好可分发版本，再分析目标。

可以点击“从 Obsidian 当前打开仓库选择”读取并验证来源候选。当前打开的仓库可以作为只读来源，但不能作为本轮写入目标；关闭目标后要重新发现并分析。若 Obsidian 配置无法可靠读取，页面会要求额外确认所有所选目标均已关闭。

## 5. Templater 分发

Templater 页接受仓库、`File` 或 `File/Templater` 目录作为来源，把解析出的 `File/Templater` 完整分发到所选仓库。目标缺少 `File` 父目录时，事务会按计划创建；撤销后，只有本批次创建且仍为空、身份未变的父目录才会移除。

## 三个分发页面的事务处理

“模板套件部署”“Obsidian 配置分发”“Templater 分发”使用相同的安全流程：

1. 分析阶段只读来源和目标，以 SHA-256 生成文件与目录的 `新增 / 更新 / 删除 / 跳过` 预览。
2. 执行前再次检查来源、目标、父目录、磁盘身份和计划完整性。过期预览会直接拒绝。
3. 所有有变化的目标先在目标自己的磁盘上完整暂存并校验；任何目标预备失败都不会开始提交。
4. 目标旧子树重命名为事务备份，暂存子树再原子切换到正式位置。多目标提交中失败会停止后续目标并按逆序恢复。
5. 完成后选择“撤销部署”可恢复旧子树；勾选独立确认后选择“确认保留”才会清理事务备份。事务记录持久保存，重新启动 ObManage 后仍可继续处理；存在多个批次时可在恢复区逐个选择。

完全相同的目标只显示跳过，不会重建目录或生成备份。事务备份与暂存目录都绑定批次 UUID、原目标、文件清单和物理身份；若被手工移动或修改，程序会拒绝自动清理并保留现场。

## 6. 回收站清理

回收站页只处理经验证仓库根目录下精确的 `.trash`，不搜索或清理笔记业务目录中其他同名文件夹。

1. 选择仓库集合根目录并扫描。
2. 查看每个仓库的文件、目录、大小和具体条目；默认不选择任何仓库。
3. 勾选要处理的仓库，核对确认文字，再开始隔离清理。
4. 清理后可选择恢复隔离内容，或确认永久清理隔离备份。

执行会先把所有选中内容复制到本机应用状态目录并逐文件校验。全部备份完成、所有预览仍有效后，才按已预览条目清理，并保留空的 `.trash` 目录。清理过程中临时出现的新项目不会被当作预览内容删除。

“已清理”只表示仓库里的 `.trash` 已腾空，隔离备份仍占用本机空间；只有“确认永久清理隔离备份”后才计算真正释放的隔离空间。恢复要求目标 `.trash` 仍为空且仍是原来的仓库和目录，发现冲突、磁盘更换或身份变化会拒绝覆盖。

永久清理只删除隔离记录认证清单中的内容。若隔离目录在操作间隙出现未登记文件或已有内容变化，程序会零删除地拒绝本次确认并保留现场；排查后可重试。多个隔离操作会列在恢复区，不会因新操作遮住旧操作。

## 设置、日志与恢复记录

应用数据默认位于 `%LOCALAPPDATA%\ObManage`，包括：

- `settings.json`：版本化、按页面分区的设置；旧版镜像设置首次迁移时保留一次备份。
- SQLite 文件：镜像内容等价记录。
- 部署事务日志：记录每个目标的暂存、切换、备份、回滚和最终清理阶段。
- 回收站隔离区及日志：用于跨应用重启恢复或最终清理。
- `obmanage.log` 与 `ui.log`：运行错误和用户可读操作记录。

便携程序仍把这些可变数据放在本机应用数据目录，不写到程序安装目录。程序数据目录必须与仓库和模板来源分离；若自定义 `--state-dir` 与任一路径相同或互相包含，程序会在日志、设置和任务写入前拒绝。移动程序时要连同 `ObManage.exe` 旁边的 `_internal` 文件夹一起复制。

## 常见失败

- **拒绝访问 / WinError 5**：先关闭 Obsidian、图片查看器、索引器等可能占用目标的程序，确认 H 盘和目标目录可写，再重新分析。若对象确实只有 Windows `ReadOnly` 属性，ObManage 只会对已验证的同一目标文件做一次有限重试；ACL 权限不足、文件占用、身份变化或其他非只读拒绝不会用 `chmod` 绕过，并会停止后续删除、保留可恢复备份。
- **预览已过期**：来源、目标、目录身份或磁盘在分析后改变。重新扫描/分析，不要绕过检查。
- **链接或特殊文件**：把链接移出要管理的子树，或改用普通目录；程序不会跟随链接复制或删除外部内容。
- **待恢复 / 待确认批次**：返回对应页面，查看持久批次状态并选择恢复或确认保留。不要先手工删除事务目录。
- **恢复记录或认证密钥损坏**：程序会停止新的写操作，而不是生成一套新记录绕过旧状态。保留应用状态目录并查看日志；不要手工伪造或替换记录。
- **目标 `.trash` 已有新内容**：恢复会拒绝覆盖。先人工判断新内容，再重新选择处理方式。
