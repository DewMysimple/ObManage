# ObManage 使用指南

ObManage 2.5 用七个独立页面管理一组本地 Obsidian 仓库。左侧选择功能；右侧完成范围选择、只读分析、来源或目标选择和执行确认。程序同时只运行一个任务，切换页面不会让两个任务并发修改仓库。

同一状态目录下如果 ObManage 已经在运行，再次打开 `ObManage.exe` 会把已有窗口恢复并置于前台；不会再启动第二个窗口。窗口若已进入系统托盘，也会重新显示。

## 共同原则

- “仓库集合根目录”可以包含多个子仓库。只有真实、可读取的普通 `.obsidian` 目录才构成仓库标记。
- 来源始终只读；部署、完整镜像和无视频备份只写页面明确显示的目标。
- 分析或统计可取消。任何输入、方向、组件或目标选择改变后，都要重新分析并重新确认。
- 路径列的完整值会显示在悬停提示中；统计和分发页保留相应复制入口，回收站页不提供复制所选路径功能。
- 链接、目录联接、其他重解析点、特殊文件、大小写歧义路径和越界路径会被拒绝，不会跟随到仓库外。
- 操作失败时先查看页面状态和“操作日志”。不要手工删除带有 `.obmanage-` 前缀的待处理事务目录。
- 左侧出现“待恢复事务”时，先进入对应页面处理部署事务或升级前遗留的回收站隔离批次；处理完成前新的镜像、部署、清理和定时镜像都会暂停。

## 1. 仓库镜像

各页面的仓库位置都有三个入口：

- **仓库列表**：搜索已登记仓库（包括已关闭的仓库）及当前选择范围内的仓库，核对完整位置后选择。
- **当前运行**：只读检查 Windows 中实际属于 Obsidian 的仓库窗口，并匹配有效的登记路径。一个明确结果会填入当前位置；多个结果显示列表供选择。同名路径、无法识别的自定义窗口标题或权限问题会提示，不能确认时不会随意填入。该功能不启动 Obsidian、不安装插件、不改动仓库；窗口关闭后保存的 `open` 标记不会被当作运行证据。
- **浏览**：直接选择文件夹，也可在输入框编辑路径。集合根输入中选择单个仓库时，扫描范围就是这个仓库，不会自动换成上级目录。

小窗口中选择按钮会分行排列，路径仍可完整悬停查看。更换路径后，旧预览和破坏性确认失效；镜像定时也会暂停。

镜像页固定显示“本机仓库”和“移动硬盘仓库”。“带到移动硬盘”以本机为来源，“带回本机”以移动硬盘为来源。所选文件夹就是镜像根目录，不会自动多套一层。

1. 核对两个位置与方向。
2. 点击“分析差异”。分析读取两边，并把已完成的内容校验记录写入本机应用状态目录。
3. 查看新增、更新、删除和跳过；“实际修改位置”全部位于本轮目标。
4. 勾选方向确认，点击“更新本机”或“更新移动硬盘”。

每轮以来源为准，目标独有内容会删除；两边各自修改时，程序不会合并冲突，也不会自动选择时间较新的版本。普通复制先写目标盘临时文件，再读取临时副本完成 SHA-256 校验，新增与更新成功后才进入删除阶段。大量小文件会合并重复的磁盘身份复核和界面刷新；来源与目标位于不同卷时，程序最多提前暂存下一个文件，与当前文件的写后读取校验重叠，同卷则保持串行。若本轮没有删除项，复制后的完整来源/目标检查就是最终屏障，不再立刻重复扫描同一个终态。每个实际文件仍检查路径链、来源/目标快照，长文件及每批文件之间也会复核磁盘与根目录身份。来源完全为空而目标有内容时，需要额外确认。

“完整内容校验”会重新读取两端全部普通文件并计算 SHA-256。两端位于不同卷时会并行读取；它仍是全量校验，速度取决于较慢磁盘。取消后已完成的常规校验记录可以继续复用。

### 定时与托盘

定时默认关闭，可选择间隔或每日时间。开启即代表授权当前绑定方向自动镜像，包括删除。

- 切换方向或修改任一镜像路径会暂停定时。
- 忙碌时到点会跳过本轮，不累计补跑。
- 有待恢复部署或升级前遗留隔离批次时到点也会跳过，避免新写入破坏撤销依据。
- 磁盘未连接会记录原因，下次到点重新检查。
- 空来源可能清空目标时，定时会暂停并要求手动处理。
- 关闭窗口时，如有后台任务或定时已启用，程序进入托盘；托盘中的“退出”才会安全停止后台任务并结束程序。

## 2. 仓库增量处理

适用于两台设备上不同仓库分别有编辑的情况。例如 A 的权威版本在移动硬盘，B 的权威版本在电脑：可将 A 设为“移动硬盘为源”、B 设为“电脑为源”，一次确认后按各自方向更新。

1. 在“电脑仓库集合”和“移动硬盘集合”中选好两端集合根目录。
2. 点击“扫描对应仓库差异”。仓库按集合内的相对路径配对，例如 `工作/A` 对应另一端的 `工作/A`；不会仅凭末级文件夹同名跨位置配对。也可以直接选择两端的单个仓库，此时对应路径显示为 `.`。
3. 扫描只读取仓库，以已验证内容和目录结构判断差异。默认快速扫描复用两端完整快照均未变的校验记录，首次或变化文件仍校验内容；一致仓库隐藏，不同内容、单端独有项及异常会列出。需要重新读取所有内容时，勾选“完整内容校验”。数量、时间都不表示哪一端更正确。
4. 每行“本轮来源”默认“暂不处理”。逐个指定“电脑为源”或“移动硬盘为源”；仅处理所选仓库范围，包含其中的嵌套子仓库，其他独立仓库保持原样。即使来源文件更少，也可以选它作为权威版本。
5. 选中仓库，下方两个方案页签可以分别查看两种方向的具体新增、覆盖、删除及完整目标路径；仅切换方案页签不改变本轮来源选择。
6. 核对列表来源及下方所选仓库数量、复制大小、删除总数，勾选确认，点击“执行所选仓库更新”。修改路径会清除旧预览和来源选择；重新扫描重置选择；修改任一仓库来源或离页会撤销执行确认。

这个工作台包含所有普通文件，包括视频、`.obsidian` 和 `.trash`；它不是“仓库备份”的排除视频模式。每个仓库按所选来源做单向镜像，目标独有内容将删除，不进行仓库内部的逐文件冲突合并。如果两端同一个仓库都有需要保留的独立编辑，应先人工整理再同步。

仅一端存在的仓库可选择把它复制到另一端相应的缺失位置，不能选择不存在的一端为来源。已有但未识别为仓库的对应目录会显示异常并拒绝覆盖；集合中无法读取或不安全的路径会使扫描不完整，并阻止整批执行。父仓库包含嵌套子仓库时，二者均可查看，但不能在同批选择重叠范围；选择父仓库会按其方向处理其中内容。

执行前先复核所有所选仓库，任一陈旧预览都会在整批写入前被拒绝；随后逐仓库串行执行，并继续使用目标暂存、完整写后 SHA-256、来源只读和删除屏障。失败或取消后停止后续仓库，已完成部分保留，表格显示已完成、未完成与未执行；整批不是可回滚事务，须重新扫描后再操作。待恢复部署或旧版回收站批次同样会阻止新写入。该工作台没有自动定时执行。

扫描只做一次内容比较，两个方向共用同一轮清单与比较结果；不是反方向再扫一次。页面显示仓库进度、扫描模式及耗时。快速扫描不等于逐次读取全部内容：若内容变化但大小、时间及身份等受检查元数据完全不变，可能继续复用记录；怀疑静默损坏时使用完整内容校验。首次校验和完整校验仍受文件总量及磁盘读取速度限制，可能需要数分钟。

日志中的“计划更新（尚未完成）”仅表示待执行方案；执行结束另报每个仓库实际完成情况和复制量，错误会带具体仓库名。

Windows exFAT 可能对仅大小写改名返回成功但未改名。程序会检查实际名称，必要时使用不长于原名的唯一临时同级名称完成改名，保持身份检查和来源只读；第二步失败时尝试恢复原名。它不是断电事务，若进程在两步之间被强制结束，可能留下临时名称，内容不会主动删除；保留现场并重新预览，不要手动批量删除疑似临时目录。

## 3. 仓库备份（排除视频）

仓库备份页为容量有限的笔记本维护一份轻量 Obsidian 仓库。它固定显示“笔记本轻量仓库”和“移动硬盘完整仓库”，首次打开时笔记本端默认指向桌面的 `ObsidianTest`。

1. “移动硬盘 → 笔记本”：以完整仓库为准，把全部非视频内容更新到笔记本；来源视频不复制。
2. “笔记本 → 移动硬盘”：以笔记本轻量仓库为准，把非视频编辑带回完整仓库；移动硬盘已有视频不覆盖、不删除。
3. 点击“分析非视频差异”并核对新增、更新、删除和“排除视频”。
4. 勾选本轮确认，再更新目标。离开页面、切换方向或修改路径都会撤销确认并使旧预览失效。

除视频外，它与仓库镜像使用相同的目标写入、安全顺序和优化后的复制内核：一次只选择一个来源，来源只读，非视频目标独有内容属于删除范围；复制文件先在目标盘暂存并校验，异卷时最多让下一文件暂存与当前文件写后校验重叠，全部新增和更新成功后才删除。没有删除项时不会连续重复最终全树扫描。进度条按“复制 + 写后校验”的总体工作量单调前进，顶部阶段文字不会随每个小文件反复闪烁。若排除视频后来源没有可管理内容，而目标有非视频删除项，会要求额外确认。它不是冲突合并工具，方向选错仍可能用来源版本覆盖或删除目标的非视频修改。

视频通过扩展名识别，当前包括 `.3g2`、`.3gp`、`.asf`、`.avi`、`.divx`、`.f4v`、`.flv`、`.m2t`、`.m2ts`、`.m2v`、`.m4v`、`.mkv`、`.mov`、`.mp4`、`.mpe`、`.mpeg`、`.mpg`、`.mpv`、`.mts`、`.ogv`、`.qt`、`.rm`、`.rmvb`、`.vob`、`.webm`、`.wmv`。大小写不影响识别；`.ts` 为避免误伤 TypeScript 文件，不按视频排除。仅仅把视频改成未知扩展名会使它按普通文件参与同步。

“完整校验非视频内容”会绕过此模式自己的快速记录，读取并比较两端全部非视频文件；视频内容始终不读取。普通完整镜像与无视频备份使用不同的校验记录，避免两个范围互相误用缓存。

## 4. 仓库统计

统计页全程只读。

1. 选择仓库集合根目录。
2. 选择是否读取 Markdown 内容并统计 UTF-8 解码后的 Unicode 字符，以及是否包含仓库根级 `.trash` 的全部内容。
3. 点击“开始统计”。

页面顶部汇总全部仓库、全部文件、内容总大小、Markdown、字符和警告；“逐仓库统计”列出每个仓库的文件、文件夹、容量与 Markdown 数量。下方“文件类型构成”按扩展名汇总 Markdown、Obsidian 画布、图片、视频、音频、PDF、Word、Excel、PowerPoint、电子书、压缩包、代码、数据、文本、字体和其他文件，并显示实际出现的扩展名、文件数、大小与占比。选中一个或多个仓库时，类型表会显示所选范围；点击“显示全部仓库”恢复总览。完整路径和详细分类可通过悬停查看。

“内容总大小”是所有已安全观察到的普通文件逻辑字节之和，不包含目录本身占用，也不等于 NTFS 实际分配空间。默认排除 `.obsidian`、根级 `.trash`、已经单独识别的嵌套子仓库和应用事务目录，避免把设置、已删除内容、子仓库或恢复副本重复计入；根级 `.trash` 里残留的 `.obsidian` 也不会被当成活动仓库或分发目标。无法按已知扩展名识别的文件仍会计入总数和总大小，并归到“其他文件”。

字符统计会在逐目录验证安全边界后并行读取最多四个 Markdown，仍逐文件复核身份与变化，不使用元数据缓存跳过正文。关闭字符统计后仍统计全部文件、文件夹、容量和类型，只读取元数据，适合快速查看仓库规模。无法读取、无效 UTF-8、文件在扫描期间变化或晚出现的目录项会形成可见警告，并把对应结果标为“部分统计”，不会静默当作精确结果。

## 5. .comSync

原“.obsidian同步”“模板套件”和“.Templater”已整合到此页面。来源、组件、目标与预览集中操作；升级后会承接原页面设置，原有待恢复批次都可在此处理。

| 组件 | 对应目录与规则 |
| --- | --- |
| `.claude` | 完整同步仓库根下 `.claude` |
| `.claudian` | 完整同步仓库根下 `.claudian` |
| `.obsidian` | 完整同步 `.obsidian`，包含插件、主题、工作区与设置 |
| `.Templater` | 完整同步 `File/Templater` 模板内容 |
| `.File` | 包含 `.Templater` 的相同内容，并补齐 `File/Note`、`File/Attachment` 两个目录 |

`.Templater`、`.File` 是组件名称，磁盘路径实际为 `File/Templater` 和 `File`，不带前导点。选中 `.File` 时会包含并锁定 `.Templater` 勾选，同一份模板只同步一次。Note、Attachment 已存在时保留目录及全部内容；缺少时创建空目录，来源的笔记、附件和其他 File 子目录不会复制到目标。选中的配置与模板则按来源完整同步，目标独有内容会删除；来源缺少选中组件时预览报错，不会当作空来源清空目标。

1. **选择来源和组件**：使用“仓库列表”“当前运行”或“浏览”，选择来源仓库或模板套件根目录，勾选需要同步的组件。默认仅选 `.obsidian`。旧设置中的 `.obsidian`、`File` 或 `File/Templater` 直接路径仍可解析。
2. **扫描并勾选目标**：选择仓库集合根目录并扫描。目标默认不选，来源及重叠范围自动排除。可逐项勾选，或用“全选列表”添加当前搜索结果、“清空选择”取消全部勾选。
3. **快速选择最新仓库**：本页的“最新仓库”按扫描时读取的仓库根文件夹创建时间选择最新目标，同一时间的仓库一起选中；会替换当前勾选并清空搜索。表格显示创建时间。它不按修改时间，也不自动执行同步；复制到新位置的文件夹可能具有新的创建时间。新建仓库后请重新扫描。任何候选时间不可读时此按钮不可用，读取问题会显示，可改为手动勾选。
4. **预览并同步**：核对新增、更新、删除的具体位置和目录补齐项，勾选确认后点击“开始同步”。长路径可悬停查看或右键复制。完成后在“同步备份 · 保留或撤销”中处理本次批次。

从来源列表读取过的集合会复用，改集合路径则重新扫描；切换来源清除目标选择、旧预览和确认。更改组件或目标也会使旧预览失效。当前打开的仓库可作为只读来源，但不能作为写入目标；占用状态无法可靠读取时，页面会要求额外确认目标均已关闭。

### 同步事务与恢复

1. 分析阶段只读来源和目标，以 SHA-256 生成文件与目录的 `新增 / 更新 / 删除 / 跳过` 预览。
2. 执行前再次检查来源、目标、父目录、磁盘身份和计划完整性。过期预览会直接拒绝。
3. 所有有变化的目标先在目标自己的磁盘上完整暂存并校验；任何目标预备失败都不会开始提交。
4. 目标旧子树重命名为事务备份，暂存子树再原子切换到正式位置。多目标提交中失败会停止后续目标并按逆序恢复。
5. 完成后选择“撤销部署”可恢复旧子树；勾选独立确认后选择“确认保留”才会清理事务备份。事务记录持久保存，重新启动 ObManage 后仍可继续处理；存在多个批次时可在恢复区逐个选择。

新创建的空目录也纳入事务；如果确认前在其中添加内容，撤销会因快照变化而拒绝删除，以保留新增内容。已存在的 Note、Attachment 仅校验目录身份，不进入内容替换或恢复授权。

完全相同的目标只显示跳过，不会重建目录或生成备份。事务备份与暂存目录都绑定批次 UUID、原目标、文件清单和物理身份；若被手工移动或修改，程序会拒绝自动清理并保留现场。

## 6. .Trash

回收站页只处理经验证仓库根目录下精确的 `.trash`，不搜索或清理笔记业务目录中其他同名文件夹。

1. 选择仓库集合根目录并扫描。
2. 查看每个仓库的文件、目录、大小和具体条目；所有非空回收站会默认选中，空项不会选中。
3. 按需取消不想处理的仓库，核对文件数、目录数、内容大小和完整位置。
4. 勾选“直接删除且无法恢复”的确认，再清理所选回收站。

执行不会创建隔离备份。程序先重扫所有所选回收站；任一仓库与预览不一致，就在删除前拒绝整个批次。复核通过后按预览逐文件、逐目录直接删除，并保留 `.trash` 根目录。清理过程中临时出现的新项目不会被当作预览内容删除。

直接删除不可撤销。确认后若遇到权限错误、取消或执行期并发变化，已经删除的内容不会回滚，页面会明确显示已删除数量和已移除内容大小；重新扫描后再决定是否处理剩余项。显示的内容大小是已删除文件的逻辑大小，不等同于文件系统保证的实际可用空间增量。

升级前若已有 2.0.0 回收站隔离批次，页面会临时显示“旧版隔离批次（升级兼容）”。这些旧批次仍可恢复或确认永久清理；程序不会自动删除旧备份。全部处理完成后兼容区隐藏，后续直接清理不会再产生新批次。

## 7. .Archive

1. 通过“仓库列表”“当前运行”或“浏览”选择单个仓库或包含仓库的集合文件夹。整个选定范围都会进入清单，包含配置、普通 `.trash` 内容及空目录。
2. 选择“自选文件夹”或“百度同步文件夹”，浏览保存位置。勾选“记住保存位置”后，下次沿用各自的位置；取消则不持久保存目录。输出不能位于来源内部，可以保存到来源的上级目录，例如桌面。
3. 压缩包名称留空时自动使用“来源名_日期时间.zip”，也可自定义。已有同名包会要求更换名称，不会覆盖。
4. 按需勾选“排除视频”，与仓库备份使用同一组扩展名，`.ts` 代码仍保留。选择压缩方案：0 仅打包、1 速度优先、6 均衡、9 体积优先，也可自定义 0–9。图片和视频等已压缩文件提高级别未必明显变小。
5. 点击“预览打包”，核对文件数、原始大小、排除项、包内相对路径及完整输出位置。改变来源、位置或参数会使旧预览失效。
6. 点击“开始打包”。程序在保存目录创建临时包，保持来源只读，保留空文件夹；直接从 ZIP 读取内容验证 SHA-256 和目录清单，并复核来源，再发布为正式 `.zip`。无需额外解压一份。ZIP 内直接是来源文件夹的内容，不另套一层同名目录。大包启用 ZIP64。
7. 使用百度同步文件夹时，可勾选“完成后打开百度网盘”，并选择自己的 `BaiduNetdisk.exe`。只有打包校验成功后才打开；无法打开客户端也会保留已完成的压缩包并显示原因。请自行确保所选目录已配置为百度同步目录，实际上传进度和结果在客户端查看。

不跟随链接或重解析点，应用的 `.obmanage-deploy-*` 事务恢复目录显示为排除项。不可读取或变化的来源会停止操作；失败/取消时仅清理本次可核验身份的临时文件，不发布不完整 ZIP。强制退出或断电可能留下 `.obmanage-archive-*.partial`，程序不会把它当成成功压缩包，也不会猜测删除未知残留。打包前按未压缩大小与目录开销检查可用空间；部分磁盘还有限制单文件大小，出现错误时换位置或调整范围后重试。

## 操作日志筛选

点击左下角“查看操作日志”，可组合使用：

- 时间：全部保留记录、今天、最近 24 小时、最近 7 天或自选起止时间（包含边界秒）。
- 功能与事件：例如 `.Archive` 的打包、仓库镜像的分析差异、回收站的清理。
- 单次任务：选择带时间和标识的一次操作，查看开始、结果和错误；切换工作台不会改变任务归属。
- 状态与关键词：筛选失败、提醒、成功、取消，或搜索仓库名、路径及日志内容；空格分隔的词需同时匹配。

新记录按最新在上展示，筛选条件在新日志到来时保留。“重置筛选”恢复全部，“复制筛选结果”包含所有匹配记录。为保持界面响应，超过 2,000 条匹配时只显示最新 2,000 条并明确提示；选择更早的时间段可查看更早记录。旧版纯文本记录归为“历史日志”，没有功能和任务标签，仍支持时间及关键词筛选。读取损坏或不可访问的记录会提示问题，不默认为完整历史。

结构化日志按约 2 MB 轮转，保留当前文件和四份历史，不是无限期审计存档；旧版 `ui.log` 和上一份记录兼容读取。文本兼容副本与新记录不会重复展示。筛选与复制不删除日志。

## 设置、日志与事务记录

应用数据默认位于 `%LOCALAPPDATA%\ObManage`，包括：

- `settings.json`：版本化、按页面分区的设置；旧版镜像设置首次迁移时保留一次备份。
- SQLite 文件：完整镜像与无视频备份相互隔离的内容等价记录。
- 部署事务日志：记录每个目标的暂存、切换、备份、回滚和最终清理阶段。
- `trash-operation.lock`：回收站直接清理使用的跨进程互斥；不包含仓库内容。
- 升级前遗留的回收站隔离区及日志：只用于兼容恢复或最终清理，不会由新操作创建。
- `obmanage.log` 与 `ui.log`：运行错误和用户可读操作记录；界面中最新记录位于顶部，向下滚动查看更早记录。

便携程序仍把这些可变数据放在本机应用数据目录，不写到程序安装目录。程序数据目录必须与仓库和模板来源分离；若自定义 `--state-dir` 与任一路径相同或互相包含，程序会在日志、设置和任务写入前拒绝。移动程序时要连同 `ObManage.exe` 旁边的 `_internal` 文件夹一起复制。

## 常见失败

- **拒绝访问 / WinError 5**：先关闭 Obsidian、图片查看器、索引器等可能占用目标的程序，确认 H 盘和目标目录可写，再重新分析。若对象确实只有 Windows `ReadOnly` 属性，ObManage 只会对已验证的同一目标文件做一次有限重试；ACL 权限不足、文件占用、身份变化或其他非只读拒绝不会用 `chmod` 绕过。镜像和部署按各自事务规则停止或回滚；回收站直接清理会保留无法删除的项并报告不可恢复的部分结果。
- **预览已过期**：来源、目标、目录身份或磁盘在分析后改变。清单复核失败会报告源端/目标端根目录、变化路径及新增、消失、大小、时间或文件标识变化；最多列出 8 项并提示其余数量。这些是快照变化，不等于已确认正文被修改。增量页还会标明失败仓库；长诊断可通过状态悬停、表格状态悬停或操作日志查看。若出现 `.obsidian/workspace.json` 或插件配置变化，请先退出 Obsidian 或停止其他写入工具，再重新扫描，不要绕过检查。
- **完成 0/N 且本批尚未写入**：在进入仓库执行前已经停止，旧差异仍然存在，并非同步成功后又出现差异。若显示“执行中已停止”，则可能已经有部分修改，应查看逐仓库实际结果；重新扫描不会自动重试写入。
- **链接或特殊文件**：把链接移出要管理的子树，或改用普通目录；程序不会跟随链接复制或删除外部内容。
- **待恢复 / 待确认批次**：返回对应页面，查看持久批次状态并选择恢复或确认保留。不要先手工删除事务目录。
- **恢复记录或认证密钥损坏**：程序会停止新的写操作，而不是生成一套新记录绕过旧状态。保留应用状态目录并查看日志；不要手工伪造或替换记录。
- **回收站清理未完整完成**：已删除内容无法恢复。先查看页面报告的删除数量和首个问题，再重新扫描剩余项。
- **旧版隔离恢复时目标 `.trash` 已有新内容**：兼容恢复会拒绝覆盖。先人工判断新内容，再重新选择处理方式。
