# 仓库镜像单次诊断

`tools/profile_mirror_once.py` 用当前普通 `SyncEngine` 分析和执行一轮镜像，默认只读。它不使用逐仓库增量实验，不切换无视频模式，也不使用其他复制工具。镜像算法和安全校验保持原样。

本工具固定 Windows 本机 E: 到移动端 H: 的方向，具体端点由操作者提供。以下变量必须是经过核对的完整绝对路径。

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/profile_mirror_once.py `
  --source $source --target $target --dry-run

.\.venv\Scripts\python.exe -X utf8 tools/profile_mirror_once.py `
  --source $source --target $target --execute --verify-deep
```

每次启动都重新分析；先前 dry-run 的计划不能加载执行。`--execute` 只请求进入现场确认，不能代替确认。工具只从本地 Windows console 读取当下 `MIRROR_TO_H_摘要` 短语，不接受管道、环境变量或参数预授权。输入也表示操作者已暂停编辑器及同步客户端等外部写入。存在删除时，还需单独输入包含文件数、目录数和同一摘要的删除短语。

确认绑定本进程预览 ID、完整清单、计划项目、统计、模式、路径、卷与根/锚点身份。预览最长 10 分钟，过期或内容变化立即停止。工具先再次调用 `validate_plan`，`execute` 内部完整预检和所有屏障继续运行。一次进程最多调用一次 `execute`；失败或取消不自动补跑。

## 写入与恢复门禁

使用真实默认应用状态目录和 `acquire_instance_lock`，不接受替代 state 参数。实例占用时正常退出已有程序后再运行，不强停或绕锁。复用 `require_recovery_clear`，待恢复部署、旧隔离批次及不可认证记录均阻断。设置、SQLite 和报告必须在两端之外。

检查根路径、实时链、卷 GUID/文件系统、磁盘映射、根和锚点身份，拒绝相同/包含范围、路径别名、同卷或同物理盘。设备总线来自 Windows Storage 查询；未知类型保留未判定。目录权限用只请求权限的句柄检查，不在仓库创建探针文件。来源空而目标非空直接停止，不传 `allow_empty=True`。

容量预检要求待复制逻辑字节，加一个最大暂存文件，以及至少 4 GiB 或待复制量 10% 的余量；这比引擎自身的逻辑字节预检保守。该数值不是实际峰值占用预测，也不通过删除用户文件腾空间。

默认要求目标直接父目录存在，避免引擎的 `makedirs` 创建目标树外的目录。操作者如另行明确授权创建该父目录，可额外使用 `--create-target-parent`。这只允许创建一个缺失的直接父目录：将路径及已有锚点身份纳入计划摘要，在现场确认和完整预检之后独占 `mkdir`。多级缺失或预览后其他程序创建该父目录都会停止；不递归创建祖先，失败保留已经创建的目录。

## 计量范围

复用 `ScanMetrics`，显式 `detail_phases` 才保留分端归因和有界阶段汇总。`phase`、目录枚举和复制调用以 `perf_counter_ns` 计时；内部现有报告仍提供 seconds 兼容旧工具，新的 JSON 和 CSV 将耗时转换为 ms。不开启指标时不收集路径和清单。

| 范围 | 指标与含义 |
| --- | --- |
| 顶层墙钟 | precheck、analysis、space_check、confirmation、confirmed_plan_revalidation、target_parent_prepare、execute、post_quick_rescan、post_deep_verify；报告写入在计时范围外，确认等待单独计时 |
| 初次清单 | source_scan / target_scan 包含真实 `_scan` 的遍历和路径元数据检查；缺失目标只有缺失状态查询 |
| 规划与内容 | planning 包含 SQLite、比较和必要哈希；source_sha256 / target_sha256 在哈希线程内计量 |
| 分析末次复核 | final_revalidation 中的 analysis_final_source / analysis_final_target；其前的根复核包含在 analysis 总墙钟 |
| 执行预检 | execute_preflight、preflight_source / preflight_target；额外的确认后 validate_plan 单列，不混入 execute |
| 文件流水线 | copy_pipeline 是完整循环及线程汇合/清理的墙钟；source_to_stage 含来源核验、复制、来源摘要及关闭输出缓冲 |
| 写后与发布 | staged_sha256、set_timestamps、atomic_publish、postwrite_recheck、copy_baseline；SQLite finalize / commit 嵌套 |
| 安全与删除 | final_barrier、barrier_source / barrier_target、delete_stage、post_delete_revalidation；失败仍保留范围异常计数 |
| 基线 | sqlite_open/read/write/finalize/register_temp/unregister_temp/close，显式 sqlite_commit 次数与耗时；baseline_hits 及 baseline_stale_records |

两种 worker 均使用现有 `copy_context().run` 传播当前聚合对象；专项测试核实工作线程中的真实哈希与复制计数。异卷预存下一文件与当前校验可并行，不能相加得到总墙钟。首末时点及成功/失败/取消次数是按范围聚合，不保存每文件事件。

`effective_mirror_MiB_s` 是已提交逻辑字节除以 execute 墙钟。`copy_phase_MiB_s` 仅在成功且有完整 copy_pipeline 墙钟时计算。source_read 是 Python 流读调用时间，stage_write 不含全部关闭缓冲成本，均不代表设备标称速度或断电持久保证。

API 请求计数不等于硬件 IOPS；受计量 SHA 流字节不等于总线流量。部分句柄和 WinAPI 调用不在 metadata_queries 范围。未做无插桩 A/B 对照，不能声称插桩零开销。缓存、杀毒及系统负载未控制，单轮不能给统计平均或置信区间。阶段范围嵌套，不计算互斥百分比。

## 本地报告

每次独占创建 Git 忽略的 `artifacts/mirror-profile/<run_id>/`；先核对报告、工作区和真实仓库之间的边界及链接链。报告写入期间固定目录句柄，只替换本轮登记且身份仍匹配的报告文件。保留阶段边界检查点；无法建立安全输出边界时只报告拒绝，不向不安全位置落盘。

| 文件 | 共享范围 |
| --- | --- |
| run_metrics.json | 固定字段、匿名计数、单调时点、自然时间、阶段状态、字节与 ms |
| timeline.jsonl | 最多 256 条不含路径的阶段与节流进度事件 |
| hotspots.csv | 顶层墙钟及嵌套累计的明确分类；不可当作互斥占比 |
| scan_mechanism.md | 当前函数调用链、扫描/缓存/复制机制及计量范围 |
| analysis_report.md、chatgpt_summary.md | 中文诊断与固定七节分享摘要；未运行项为 null / NOT_RUN |
| private_plan.json、private_plan.md | 私有：全部逐项计划、路径、身份和完整删除清单，禁止上传/提交 |
| run_local.log | 私有：复现参数和完整异常，默认禁止共享 |

分享版本不输出任意扩展名、私有文件名、笔记正文、真实路径或卷 GUID/序列号。扩展名使用固定类型分组，卷标识只保留单向摘要。报告全体均不提交 Git；需要分享时仍检查前六类输出，避免人工追加私人信息。

快速复扫和 deep 引擎复核与 execute 分开计时，失败时不重发写任务。未开启或无法完成 deep 应报告部分验证。独立第三方审计默认 NOT_RUN，避免额外两端全量读盘；不能把引擎 deep 宣称为独立实现核验。来源前后清单只证明受检元数据的观察区间，初始未读内容时不声称绝对零写入，系统可维护访问时间。
