# 扫描与执行性能验证

## 2.8.0：共享扫描

2026-11-05 在 Windows 11 / Python 3.14.2、本机同卷的临时数据上，对照固定 2.7.1（`c56a688`），25 个仓库（含嵌套）、每端 1,075 文件与 204 目录，交替运行三轮。首次增量中位耗时 3.7159 → 3.3936 秒，无变化复扫 2.4456 → 2.1965 秒，单文件同大小修改 2.4218 → 2.1580 秒；元数据统计 0.8116 → 0.7474 秒，严格 UTF-8 统计 0.9875 → 0.9308 秒。

增量每轮目录枚举 1,246 → 920 次，SQLite 连接 25 → 1 次；首次两版均完整读取 2,236 份文件版本、15,841,384 字节。统计仍有真实末次清单、发现范围和嵌套 marker 检查，执行前检查和写后完整校验保持。早期归档清单适配测出约 6% 退化后撤回，最终归档预览基本持平；目录权限异常场景因集合结束复核而更慢。

[完整架构、故障矩阵、原始口径与性能表](扫描架构与性能优化.md)记录了实际范围及未迁移模块。以下为复现命令；不是 USB/冷缓存实测或速度保证。

```powershell
.\.venv\Scripts\python.exe tools/benchmark_scanning.py --vaults 24 --files 40 --repeats 3 --output artifacts/sharedscan-verified.json
```

## 2.7.1：.comSync 批量预览

2026-11-02 在同一 Windows 开发机的隔离临时目录，对照 2.7.0（`947ccdd`）和本次源码。46 个目标选择四个内容组件及两个仅补目录意图，共 276 个组件/目标组合；每个内容组件含 20 个 1 KiB 文件，目标另含待删除文件。每版预热一次，再交替测量三轮。

| 版本 | 三轮耗时 / 秒 | 中位数 / 秒 |
| --- | --- | ---: |
| 2.7.0 | 8.4931、8.6959、8.5381 | 8.5381 |
| 2.7.1 | 5.5883、5.5321、6.0681 | 5.5883 |

这组批量小文件预览耗时缩短约 34.5%。每轮均完整读取 3,944 个文件，全部文件/目录变更与来源、目标内容清单一致。优化去重来源与授权根，并预计算路径键，避免批量包含保护反复规范化同一路径。旧版 46 目标、每组件 100 文件的剖析中，包含判断调用 382,536 次，累计约占 39% 分析时间。

首轮较大工作负载与其他验证同时运行时，前后耗时波动明显，个别旧版样本更快，因此不将那组结果作为稳定收益。上述预热后的结果也仅代表本机合成数据；实际仓库的组件数量、插件文件、磁盘冷读、杀毒和后台负载都会影响耗时，不把用户日志中的等待时间直接换算为提速承诺。

完整 SHA-256、每目标读取、大小写/路径包含保护、链接与身份检查、扫描结束清单和执行前复核均保留；不通过跳过元数据相同的文件或跨轮复用内容摘要提速。

复现（只生成临时合成仓库，不执行同步，不控制 Obsidian）：

```powershell
.\.venv\Scripts\python.exe tools\benchmark_comsync.py --targets 46 --files 20 --repeats 3 --warmups 1 --baseline-ref 947ccdd --report artifacts/comsync-preview.json
```

## 2.5.2：小文件开销与 ZIP 归档

2026-09-28 在 Windows、i7-11800H（8 核 / 16 线程）、约 16 GiB 内存的当前开发机上，用隔离临时目录比较 2.5.1（`3f4f7c4`）与本次源码。每版三轮，以下为中位数；没有读写真实仓库。磁盘缓存、杀毒扫描与后台负载没有人为关闭，不能把本机数字当作其他机器、USB 或机械盘的速度保证。

工作负载沿用下文小文件场景，每棵树改为 300 项，共 900 个文件。新增 ZIP 完整流程：先预览，再写入、复读整个 ZIP 核验 SHA-256、重读来源并检查最终清单后发布。混合场景另加 32 MiB 固定种子的二进制与重复文本；压缩等级、文件范围和校验次数前后一致。大文件同步测量也包括写后校验及最终扫描。

| 操作 | 2.5.1 / 秒 | 2.5.2 / 秒 | 耗时变化 |
| --- | ---: | ---: | ---: |
| 小文件 ZIP 预览 | 1.3006 | 0.3092 | −76.2% |
| 小文件 ZIP 完整执行 | 2.0799 | 1.0726 | −48.4% |
| 混合 ZIP 执行，等级 0 | 2.1681 | 1.1504 | −46.9% |
| 混合 ZIP 执行，等级 1 | 2.4082 | 1.4099 | −41.5% |
| 混合 ZIP 执行，等级 6 | 2.5645 | 1.5603 | −39.2% |
| 300 个修改文件的镜像执行 | 1.6824 | 1.5393 | −8.5% |
| 300 个修改文件的无视频备份执行 | 1.7389 | 1.5177 | −12.7% |
| 32 MiB 文件镜像执行 | 0.1930 | 0.1939 | +0.5% |
| 首次镜像比较 | 1.2779 | 1.2898 | +0.9% |
| 有基线的镜像扫描 | 0.1174 | 0.1199 | +2.1% |
| 精确字符与文件统计 | 0.0795 | 0.0777 | −2.3% |
| 逐仓库增量扫描 | 1.5660 | 1.7002 | +8.6% |
| 三目标部署执行 | 4.8418 | 4.8583 | +0.3% |

增量扫描三轮整体结果上浮 8.6%，因此又在同一份文件上交替运行旧/新 `ReadScope`（首次分析会经过的唯一相关实现改动），各三次、每次使用新的基线数据库。中位数为 0.6065 / 0.6074 秒（+0.15%）；旧实现第一次为 1.4477 秒，随后为约 0.606 秒，说明首次打开文件的环境开销足以明显影响这一短任务。保留原始整体数字，不据此声称增量首次扫描提速；同输入的受控对照未显示明显的实现退化。

另用 2,000 个 1 KiB 相同文件，先建立正向校验记录，再单独测量第一次反向扫描。三轮中位数从 0.2976 秒降至 0.1601 秒（−46.2%）。反向扫描现在直接使用既有持久记录，不再把相同结论逐文件提交一遍；两端精确快照及最后清单仍复核，完整内容校验仍会先退役旧记录。

改动边界：

- ZIP 只读扫描与来源复核复用 `ReadScope`：同目录最多 16 项或 250 ms 共享祖先查询，每个叶子仍读取实时状态。目录结束复核、文件句柄、读后状态、完整内容和最终清单屏障均保留；压缩写入期仍逐文件完整核验来源路径链。
- 同卷不超过 64 KiB 的文件在既有任务线程直接完成暂存，减少逐文件线程调度。超过该大小或异卷仍使用一个来源写 worker；没有新增无界并发，也没有改变全局任务槽、写后 SHA-256、逐文件基线提交和失败停止删除。
- 部署事务使用紧凑 JSON 一次编码写入，减少缩进编码和日志字节；原认证内容、修订、原子替换及 `fsync` 不变，旧缩进记录兼容。本组部署耗时没有显著下降，不声称其整体提速。
- 保持原压缩算法和用户选择的等级；不通过跳过正文、降低压缩级别或缩减校验提高数字。GPU 不参与这些文件处理；没有针对某台机器降低质量的模式。

复现当前版本：

```powershell
1..3 | ForEach-Object { .\.venv\Scripts\python.exe tools\benchmark_io.py --files 300 --large-mib 32 --output "artifacts/benchmark-$_.json" }
.\.venv\Scripts\python.exe tools\benchmark_io.py --reverse-only --files 2000 --output artifacts/reverse.json
```

`--reverse-only` 自带三轮。基准不接受真实仓库路径；生成数据、清理和首次建立基线不计入反向扫描计时。常规模式保留各阶段耗时，便于看到没有收益或有波动的项目，而非只展示最快结果。

## 共用实现与边界

- [reading.py](../obmanage/reading.py) 提供大小自适应缓冲、复用内存的完整 SHA-256 流和单轮只读路径检查范围；镜像、备份、增量扫描、部署校验、回收站及统计使用相应公共部分。
- 只读内容检查对连续同目录文件共享祖先检查，最多 16 个文件或 250 ms，换目录立即重查。每个文件仍检查当前路径、打开句柄、大小和时间；最终完整清单与目录链复核不省略。该范围不跨扫描轮次，不用于文件系统写操作。
- 实际复制、替换、改名、删除仍使用完整的具体路径链检查。没有减少部署的全目标准备屏障、来源重读、目标/暂存树完整内容校验、持久恢复或独立的备份清理确认。
- 回收站复用相同的安全子路径检查，消除重复 `realpath`；仍检查每级祖先和叶子，不因旧清单扩大删除授权，并新增打开句柄的内容身份及读取期检查。
- 仓库发现只排序待遍历的子目录，父仓库关系按祖先查表，避免对所有仓库两两比较。占用校验只验证登记的精确仓库根，无需遍历其笔记。
- 部署复制进度只计算一次总字节，避免每复制一个小文件都重新遍历全部来源。SQLite 逐文件持久基线、原有异卷有界复制流水线及全局单任务保持不变。

## 复现

在工程根目录使用开发环境运行：

```powershell
.\.venv\Scripts\python.exe tools\benchmark_io.py --files 200 --output artifacts\benchmark.json
.\.venv\Scripts\python.exe tools\benchmark_io.py --files 200 --profile artifacts\io-profile.txt
.\.venv\Scripts\python.exe -m pytest -q
```

基准只接收文件数量和报告位置，不接受真实仓库路径。输出保存在忽略目录，默认在独立临时目录生成及清理数据。启用 `--profile` 的耗时包含分析器开销，不应与上表直接比较。

安全回归覆盖来源只读、两个方向、视频排除、陈旧预览、长路径/链接、内容变化、取消、写后校验、多目标准备失败与回滚、恢复记录认证、回收站直接删除及新增/未选项保护。模拟故障不能替代所有真实硬件验收。
