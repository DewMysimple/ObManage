# 共享扫描：架构、验收与性能证据

本轮以 2.7.1（`c56a688`）为不可变对照，保持页面、同步方向、事务和删除流程。开发数据全部来自临时目录，不访问真实用户仓库。下文区分阶段证据和最终验收；尚未完成的迁移不能据此宣称已交付。

## 改造前调用与范围审计

| 入口 | 初次观察 | 后续工作与必要屏障 |
| --- | --- | --- |
| 仓库选择器 | 登记根精确验证、集合递归 `discover_vaults` | 仅选择路径；不授权后续写入 |
| 仓库统计 | `discover_vaults` 后再次逐仓库枚举 | UTF-8 精确读取可选；逐目录重新枚举及身份检查 |
| 增量页 | 双端发现；每对仓库独立 `SyncEngine.analyze_pair` | 逐对 SQLite 初始化、内容比较、双端末次清单；一次比较派生反向计划 |
| 镜像/无视频备份 | 双端 `_scan` | 受模式隔离的基线及完整哈希；分析末次清单、执行前及删除屏障 |
| 归档 | `_inventory` | 空目录/排除项、完整摘要、ZIP 验证与发布前来源重验 |
| 部署/回收站 | 限定子树的专用扫描 | 事务备份/认证/恢复或精确直接删除；不适合改成集合缓存授权 |

发现不进入 `.obsidian`、真实仓库根级 `.trash` 和恢复目录；镜像必须包含前两者及嵌套子仓库。统计排除配置目录并在嵌套仓库边界停止；归档保留空目录与可见排除项。这些差异由业务视图保留。

重复的首次发现/清单采集和数据库初始化可以共享。末次真实观察、打开文件句柄核验、执行前检查及写后完整 SHA-256 不能由旧观察替代。

## 阶段 0–1：初始测量

Windows / Python 3.14，本机临时目录，12 个独立仓库加一个嵌套仓库，每仓库 30 个小型 UTF-8 笔记、配置文件、256 KiB 附件、视频及空目录。两个版本交替执行三轮；操作系统缓存未受控制，没有模拟或声称 USB 实测。

原实现首次分析中位数 1.6761 秒，无变化复扫 1.1547 秒；每轮均为 588 次目录枚举、3,214 条枚举记录。复扫有 13,585 次 Python 元数据查询，首次有 18,917 次；首次完整哈希 924 次，读取 8,261,176 字节（嵌套父子范围有重叠读取）。元数据统计 0.3430 秒、精确字符统计 0.4134 秒，均有 268 次枚举。该组是优化前证据，不是最终收益表。

同组首轮中，初始与末次镜像清单合计约 0.49 秒；SQLite 打开约 0.020 秒、写入约 0.039 秒；完整哈希流约 0.023 秒。计时可能嵌套，不能相加当成互斥耗时。此小文件数据上，遍历及元数据相关固定成本比哈希流明显；大附件、冷磁盘和 USB 的组成仍需另测。

`ScanMetrics` 默认关闭，仅显式激活或开启 `obmanage.scan` DEBUG 日志时收集任务级聚合。日志不含仓库路径、文件名或正文。基准同时从真实 `os.scandir`、`os.lstat`、`os.stat`、`DirEntry.stat` 和实际内容读取计数，确保旧版与新版使用相同口径；这些是 Python API 请求数，不宣称是磁盘硬件 I/O 次数。

```powershell
.\.venv\Scripts\python.exe tools/benchmark_scanning.py --vaults 12 --files 30 --repeats 3 --output artifacts/sharedscan.json
```

基准通过 Git 只读导出固定提交，在临时目录用独立包名加载；不会切换工作区或维护第二套生产扫描器。测试也使用该独立引用比较仓库集合、完整文件/目录快照、排除项、问题代码及统计结果。

## 扫描会话的可信度

`ScanSession` 属于一个任务 epoch，有明确关闭动作，关闭时释放全部目录观察；不保留 `DirEntry`，不建立跨任务持久清单。发现阶段可用枚举元数据，进入内容清单前升级为现有 `snapshot()` 的完整字段。

Windows 实测 `DirEntry.stat()` 的 inode/device 为零，因此绝不把这些值送入镜像计划。清单使用独立路径快照；目录观察有枚举前后状态，任何异常形成不完整结果。只读统计可以报告部分结果，写操作消费清单前必须 `require_complete()`。

相邻调用可以传入刚完成的祖先链检查及目录状态，避免立即重复同一检查；这不扩展到写入阶段。末次复核必须重新枚举实时文件系统，不能将旧会话自身当成复核结果。

## 实施检查点

- 阶段 0：调用与范围审计、三轮改造前基线已完成。
- 阶段 1：可关闭聚合计量与真实磁盘基准已运行；与原有读取、发现、统计、增量及 SQLite 相关的 84 项回归通过。
- 阶段 2：目录观察、显式 epoch、清单策略、不完整状态与关闭语义的 9 项基础测试通过。
- 阶段 3：发现/统计接入任务会话，新旧独立对照及相关专项共 60 项通过。首次方案减少枚举但重复祖先检查导致耗时退化，已修正；最终收益仍以验收数据为准。
- 阶段 4：`SyncEngine` 抽取比较器，增量页接入双端集合初次采集、单一 SQLite 连接及真实集合末次复核。双方向不再重复比较；执行前整批预检及串行写入保留。
- 阶段 5：归档清单适配运行通过回归，但 13 仓库三轮中位数由 0.6621 秒增至 0.7031 秒（约 +6.2%），已撤回该适配。归档、部署和回收站保留专用遍历/执行器，共用低开销目录计量；不宣称全部页面统一清单。
- 阶段 6：680 项全量、原生八页三尺寸、ZIP 结构/CRC、解压 EXE 八页及深度只读 CLI 均通过；Git 结果以最终远端核对为准。

跨页面历史列表缓存暂未加入：原页面保留自己的结果；把历史列表与实时结果并列展示会增加新状态和失效分支。本轮先验证任务内真实共享，所有重新扫描操作继续读取当前文件系统。

## 2.8.0 最终性能验收

2026-11-05，Windows 11 10.0.26200 / Python 3.14.2，同一本地临时卷；24 个独立仓库加一个嵌套仓库，每端 **1,075 个文件、204 个目录**，含 1,000 个 UTF-8 笔记、配置、空目录、视频及每仓库 256 KiB 附件。每版三次，整组交替执行，取中位数。首次使用新状态库，复扫复用各自库，只修改一份同大小文件。文件系统缓存未控制，生成数据不计时，不称冷缓存或 USB 实测。

| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 首次增量（无基线） | 3.7159 | 3.3936 | -8.7% | 1,246 → 920 | 41,491 → 40,777 | 15,841,384 / 15,841,384 B |
| 无变化增量复扫 | 2.4456 | 2.1965 | -10.2% | 1,246 → 920 | 28,911 → 28,197 | 0 / 0 B |
| 单文件同大小修改 | 2.4218 | 2.1580 | -10.9% | 1,246 → 920 | 28,943 → 28,229 | 1,920 / 1,920 B |

首次两版均完整哈希 **2,236 份文件版本、15,841,384 字节**；父/子仓库的内容比较仍按业务分别进行，没有以复用目录观察代替内容读取。无变化复扫均无需重新哈希；少量修改均只读取两份文件版本、1,920 字节。精确统计均读取 960,000 字节，关闭字符统计均为零。数据库连接从每轮 25 次减为 1 次，逐文件持久提交保持。

目录枚举不是唯一收益指标：增量清单枚举减少约 26%，路径元数据请求仅小幅减少。更多收益来自共享首次目录观察及初始化；没有将查询数下降幅度当成总耗时下降幅度。正常增量场景约缩短 9%–11%，统计约缩短 6%–8%。

异常场景故意在每个笔记分组制造权限失败，两版均显式报告不完整并阻止写入。新版还进行集合结束复核，因此该场景耗时上升；不能将此结果当作全面提速。取消场景均在第三次发现进度发出取消，约 14 ms 返回，实际设备阻塞 IO 的取消延迟未验证。归档最终仍为原遍历，耗时基本持平。

阶段计时如下，均来自真实路径；函数范围可能嵌套，不能相加。新版 discovery 包含初次与末次的发现和清单升级，旧版该项只有初次发现；`inventory` 也嵌套于集合扫描。统计 UTF-8 数字是多个读取 worker 的累计时间。


原始逐轮 JSON 保存在本机忽略的 `artifacts/`；工具可生成相同口径的新报告。未测物理 USB、exFAT 热插拔及断电恢复速度，未作跨设备速度承诺。若继续推进归档迁移，最小下一步是先减少清单适配对象开销并重新跑同一基准；部署和清理应先单独测量限定子树，再评估只迁移枚举适配，不改执行器。
