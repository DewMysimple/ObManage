# 待恢复事务重设计

## 目标与原因

用户报告同步目录变化后，撤销和确认清理都失败，其他功能持续被恢复门禁阻止。源码确认两条路径共享旧部署快照要求，且撤销失败状态不被旧确认接口接受；用隔离目录复现，不推测具体用户文件的变化来源。

## 改动

- 版本 2.5.1；按 [ADR-010](../决策/ADR-010-事务结束与备份清理解耦.md) 分开事务结束、保全回退和副本清理。
- `resolved` 仅更新认证记录、保留仓库及全部副本，允许目录正常变化或暂时离线；全局门禁和部署服务共用终态集合。
- 恢复预览绑定批次修订和完整内容快照。回退保全当前内容，旧备份复核后恢复；认证记录兼容旧 schema 的缺省字段，保全内容不进入自动清理。
- 可选清理验证全批副本及单树陈旧预览，部分失败可重试且不重新阻塞。已结束批次禁止覆盖后续任务。
- 恢复面板置顶、先检查后确认、已结束副本继续可访问，多批次和离页确认失效保留；更新使用指南与工程约定。

## 边界

真实用户仓库与真实待处理事务均未执行恢复、结束或清理。目录身份替换、旧备份不完整或认证损坏仍阻止自动回退；认证有效时可接受现状结束，损坏记录仍需人工排查。保全内容后续取回为手动操作，保全副本不会自动删除；不扩展旧回收站隔离恢复语义。

提交和远端结果以最终 Git 核验为准，不提前记录推送成功。
