# exFAT 移动盘同步按变化复核

实测使用 Windows 确认为 USB 总线的 1 TB 外置 SSD，其 exFAT 分区被 Windows 标为 Fixed。本机目标在 NVMe 的 NTFS 分区。两端均独占新建临时目录，包含 57 个子目录、28,299 个两端相等文件、40 个来源新增、7 个同大小更新及 34 个目标独有文件。两端配对文件各 64 字节，基线预热后每轮只在临时目标恢复上述差异，通过快速预览和已预览的手动同步运行。

| 复制完成、删除前 | 枚举 58 个目录、28,403 个条目 | 枚举 0 个目录，单查 47 个文件及其路径链，复用 28,299 个跳过文件 |

两次复核合计少枚举 56,806 个条目，其中跳过文件 56,598 项次。目标仍独立核对写前、复制后、删除后的清单。逐项删除时验证来源对应路径缺失、目标仍匹配，实际复制保留来源复核和目标暂存 SHA-256 读回。表格统计的是应用枚举与路径复查，硬件实际 I/O 会受 Windows 缓存影响。

设备重新连接后的同一组文件按新版、旧版、旧版、新版、新版、旧版交替执行，无计数插桩。旧版点击至完成为 9.261、9.025、9.563 秒，新版为 4.338、4.970、4.794 秒，中位数 9.261 → 4.794 秒，约缩短 48%。两版预览中位数均为 1.962 秒。设备重连前单独测得旧版 2.782 秒，该次连接的缓存及系统状态不同，未混入配对统计。计数另跑各一轮，墙钟也不混入。所有实盘样本为合成小文件。

## 实现与故障边界

- [执行器](../../obmanage/engine.py)在写前完整重读两端。若本地 exFAT 来源至少一半普通文件可跳过，[来源跟踪](../../obmanage/source_recheck.py)在枚举目录及读取文件快照之前申请 Windows 的读取和句柄缓存许可。来源目录成员或文件数据变化会使对应许可失效，复制和准备删除的项目仍按实际路径验证。单次执行最多持有 32,768 个许可，未覆盖文件实时查询，未覆盖目录重遍其子树。Windows 需要让出句柄时响应线程立即关闭，执行器恢复完整来源核对。
- 真实设备探针显示，写入者仍打开文件时，文件大小已经可见而目录读取许可仍可能有效。文件许可捕获这个窗口。独立 exFAT 测试还发现，只改创建时间可使目录和文件许可同时保持有效，因此在首次枚举前另监测整个来源子树的创建时间和目录名。该通知触发、失效或无法取得时完整重读。许可只在执行期间持有，进入预览、等待用户和跨轮基线均不持有。[Windows 目录与文件 oplock](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_request_oplock)、[Windows 目录变化通知](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstchangenotificationw)
- 真实 USB 来源、独立本机目标分别在写前、复制中和删除后保持一个原跳过文件的写句柄打开并追加内容。镜像与无视频备份六个场景全部拦截。写前两端仓库零写，复制中保留已完成的一份复制并停止删除，删除后明确报告部分完成。
- 额外使用的 512 MiB 本地临时 exFAT 虚拟卷覆盖读取许可、创建时间、改名与回退分支。该卷和镜像文件已移除，速度对照只取上文真实 USB 数据。[变更与句柄释放回归](../../tests/test_source_recheck.py)、[单次诊断的计数字段](../../docs/仓库镜像单次诊断.md)

## 交付验证

- 单独遍历实盘来源和本机目标，并分别与造数时的预期名称、类型和 SHA-256 比较。双方 28,403 个条目全部一致，复制 47 个、删除 34 个。真实 USB 临时目录、本机样本、临时虚拟卷与镜像均已核对清除。
- 全量 973 项通过。25 项新回归另外在真实 USB/exFAT 临时目录上全部通过，覆盖持有写句柄时追加、创建时间、原子替换、大小写改名、目录及根替换、取消、许可上限及失效回退。
- 基于最终源码生成便携 ZIP，根层、使用说明和全部 236 个条目 CRC 均通过。解压 EXE 启动八页，完整校验 CLI 正常。在真实 USB 及本机临时目录中，通过原生界面快速预览后同步到本机、反向纯删除、目标变化后零写停止，三条路径通过。
