# 2026-09-11｜Windows 只读目标处理修复

- 目标：解决本机向移动盘镜像时，目标独有的 Windows 只读文件在删除阶段报告“拒绝访问”的问题，并覆盖只读旧目标的更新。
- 类型：bug。
- 状态：源码修复、产品回归、真实 exFAT 隔离验证、便携包重建、EXE 烟测及记忆检查均已完成，日志已封存。
- 日志索引：[工作日志 MOC](./MOC_工作日志.md)。

## 诊断与决定

- 只读检查确认报错对象是目标独有的普通文件，带 `ReadOnly, Archive`；目标 exFAT 卷健康、在线且非只读，父目录普通，ACL 无拒绝规则，因此不是整盘或账户权限问题。
- 前一问题修复后同步得以进入删除阶段，才暴露这条独立路径；程序在错误处停止后续项目，但此前已完成的目标侧操作不会回滚，来源未被写入。
- 隔离探针确认 Windows/exFAT 上 `os.unlink` 删除只读文件返回 WinError 5；覆盖只读旧目标可能返回 WinError 5 或 183。`os.chmod(path, stat.S_IWRITE)` 只清除 `ReadOnly`，不会清除 Archive/Hidden。
- 不把任意“拒绝访问”视为可绕过。仅对预期 Windows 错误、仍匹配预览的目标普通文件和实际只读位执行一次受控重试；清除前后复核类型、设备、文件 ID、大小、mtime 和 ctime。非只读错误、对象变化及异常属性处理仍失败。
- NTFS 硬链接共享底层文件属性；解除目标路径的只读位可能波及来源或同步根外的另一个链接。清除前后都要求硬链接计数为一，多硬链接只读文件安全失败且不执行 `chmod`。
- 二次变更失败时，仅当路径仍对应解除只读后的精确快照且硬链接计数仍为一才尽力恢复只读位；来源和目录不做 `chmod`。路径复核到路径式变更之间仍继承现有引擎的极窄并发窗口，不引入复杂且不能统一覆盖 replace 的 Win32 句柄流程。
