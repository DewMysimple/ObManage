# 事务彻底批量清理

## 目标与证据

用户反馈清除后仍显示事务和路径，要求清理完整。截图为三个已清理副本的隔离记录。本轮只读核验确认这三条记录仍在，副本及事务目录已不存在；记录最后修改时间早于本轮。既有按钮仅处理当前一条，自动选中下一条；本轮改为一次清空整批可清理事务，不推断此前点击行为的实际结果。

## 改动

- 版本 2.6.3；按钮改为“清除全部副本和记录”。先通过全局 FeatureWorker 只读检查全部已结束部署及隔离事务，再确认一次清除，完整列出整批路径及数量。
- 原认证副本删除逻辑继续适用，清除各事务目录、部署授权锚点及持久记录。已经没有副本的历史记录同批移除；成功后列表、选择器和路径详情清空，关闭弹窗释放路径内容，重启不再恢复这些条目。
- 待处理部署不会被自动结束，需先选择保留现状或回退。认证损坏、未知内容和身份变化继续拒绝删除；执行失败的事务保留记录，其他独立事务可继续清除，结果报告实际数量。
- 无 Qt 的批量服务冻结确认前集合；隔离预检读取完整内容或授权剩余子集、计算当前副本和目录数量，并绑定认证记录摘要。执行在原双锁内复核摘要，确认后新增事务不进入删除范围。
- 切换事务、离开页面、取消或检查期间上下文变化使本次确认失效；全部执行测试使用隔离临时目录。真实用户事务仅只读核验，未执行清除。
- README、使用指南、当前状态、ADR-010 和事务知识同步更新。

## 实际验证

- 最终全量回归：569 项通过，240.90 秒；最终事务服务、应用壳、隔离引擎和布局专项 89 项通过。
- 三条已清理副本的历史记录回归：取消零写入，确认一次后全部 journal、事务目录、列表及路径详情为空；重新创建窗口和重启读取仍为空。
- 混合事务回归：部署、隔离待处理及已完成记录统一整批清除；恢复后的 `.trash` 内容保留。覆盖记录变化、未知内容、执行中失败、取消、未结束部署排除及确认后新增事务保护。
- 原生 Windows：待处理/已结束部署、待处理/已完成隔离和清空状态均检查 980×620、1140×920 及真正最大化；完整路径和单次确认可访问。全页三尺寸布局回归通过。
- 最终应用源码由 `tools/build.py` 成功构建，保留干净子进程 PATH；构建前验证输出处于本工作区且无重解析点，未发现对应路径运行进程。
- ZIP 完整 CRC、根目录结构、包内 EXE 与使用说明一致性通过；冻结 EXE 的待处理部署、已结束部署及混合事务三种启动验证通过，检查零改动仓库和事务。
- 冻结 EXE 原生 UI Automation 实际点击：一次确认清除一个部署事务及三条空历史隔离记录；副本、认证记录及事务目录全部消失，当前仓库内容保留，冻结程序重启仍显示空列表。
