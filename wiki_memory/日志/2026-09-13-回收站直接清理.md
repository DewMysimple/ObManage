# 2026-09-13｜回收站直接清理

- 时间：2026-09-13（北京时间）
- 类型：`feature`
- 状态：`已完成`
- 目标：扫描回收站后默认选择全部非空项，移除回收站页的路径复制入口，并将新清理改为确认后直接删除、不创建隔离备份。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的决策

- 回收站扫描结果默认勾选全部非空 `.trash`，空项不可勾选；不可恢复确认仍默认关闭，选择、路径、重新扫描或离页会撤销确认。
- 新清理在完整重扫屏障后直接删除原预览清单并保留 `.trash` 根，不创建 `trash_backups`、`trash_journal` 或 `trash-auth.key`。删除不可撤销，取消或失败可能留下部分结果。
- 升级前由 2.0.0 创建的隔离批次不自动删除或遗忘。仅检测到旧批次时显示兼容区，继续支持认证恢复/最终清理并参与全局恢复门禁。

## 实现与审查

- `TrashCleanupEngine.execute` 保留显式选择、状态目录分离、进程内/跨进程锁、全部所选预览复核和逐项身份保护，移除新操作的复制、签名和 journal 写入链；直接结果不生成 operation ID。
- 服务层在删除前枚举遗留记录，待处理或损坏的旧隔离状态继续 fail closed，避免绕过 UI 破坏旧恢复前提。
- 最终审查补充了旧隔离命名空间一致性检查：缺少 journal 的孤立备份、journal 目录中的临时或未知项目都会阻止直接清理并保留现场。
- 回收站页移除仓库与条目区域的两个复制按钮；扫描后自动选中非空项，按钮和确认文案明确“直接删除且无法恢复”。遗留恢复面板在普通状态隐藏。
- 并行审查发现结构性路径复核若在部分删除后中断会丢失已删除计数；已修复为保留文件、目录和逻辑字节计数，并增加故障注入回归。
- README、使用指南、工程约定、现行状态、模块知识和 ADR 已同步；ADR-006 替代 ADR-005，原隔离策略保留为历史。
