# 2026-09-11｜多页面仓库管理升级

- 时间：2026-09-11（北京时间）
- 类型：`feature`
- 状态：`已完成`
- 目标：把五个旧版仓库小工具的业务意图重新设计为 ObManage 的独立页面和安全业务引擎，同时保留仓库镜像为第一页。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的决策

- ObManage 从单一镜像工具升级为多页面 Obsidian 仓库管理器；一个功能一个页面，仓库镜像固定为第一页。
- 旧脚本只作为业务需求来源，不直接嵌入或执行。控制台问答、硬编码路径、隐式全选、先删后拷、进程内备份映射、静默错误等实现不迁移。
- 统计保持严格只读；配置和模板使用限定子树事务部署；回收站内容先隔离校验，再清理、恢复或最终释放。
- 所有页面共享应用级单任务槽；镜像的既有 `SyncWorker(QThread)` 生命周期和调度语义保持不变。
- 设置升级为版本化、按功能命名空间的文档，并保留旧镜像设置的兼容迁移。

## 检查与操作

- 只读审阅五个用户提供的旧工具，提取仓库发现、统计、组件分发、Templater 分发和 `.trash` 清理语义；未运行旧工具，未用真实用户仓库做执行验证。
- 检查现有镜像路径、线程、调度、设置、布局和打包边界，保留来源只读、目标限定、陈旧计划拒绝和忙时不补跑。
- 两轮独立安全审查覆盖持久事务授权、路径越界、Windows 8.3 别名、跨会话互斥、崩溃阶段、多批次恢复、部分清理重试、设置隔离和扫描稳定性；最终未发现剩余 P0/P1/P2。
- 发现并修复程序数据目录在仓库内时日志先落盘的来源保护漏洞；CLI 和 GUI 均在日志、设置、锁和后台任务写入前拒绝相等或互相包含的位置。
- 仓库发现排除父仓库根级 `.trash` 内的已删除仓库；统计增加文件句柄/路径 epoch 复核和目录稳定双扫描，变化会明确标记为不完整。
- 使用合成设置渲染六个页面的 980×620 与 1140×920 窗口，并检查 2560×1417 最大化镜像页；无横向滚动，较长页面可纵向到达确认和恢复区。

## 文件变更

- 新增 `obmanage/management/` 的仓库目录、统计、限定子树部署、持久日志和回收站隔离服务。
- 新增 `obmanage/pages/` 的功能注册、共享页面基础、统计、三类分发和回收站页面。
- 主窗口改为静态左侧导航与页面栈，增加通用后台任务、全局取消和全局日志入口。
- 设置文档升级为 schema v2；应用元数据升级为 2.0.0。
- 重写公开 README 与使用指南，更新工程约定和合成截图工具。

## 测试与验证

- `pytest -q`：339 项通过，覆盖原有镜像、目录/统计、schema v2、部署故障与恢复、回收站隔离、全局门禁、状态目录零写拒绝和多尺寸 UI。
- 部署事务另经攻击矩阵验证密钥缺失/短写/替换、grant-only、journal-only、未知内容和当前目标丢失均 fail closed；独立审查未发现 P0/P1/P2。
- `tools/build.py` 使用干净 PATH 成功生成 `dist/ObManage/ObManage.exe`；冻结 EXE 以独立临时状态目录启动、保存界面截图并退出，退出码 0 且无残留进程。
- 已更新公开演示截图；六页 980×620、1140×920 和最大化视觉检查通过。
- 工程记忆索引已刷新；`memory_lint.py check` 检查 30 页通过，记忆工具自身 12 项测试通过。
- 所有新增文件系统测试均使用 pytest 临时目录；真实仓库未被写入。
