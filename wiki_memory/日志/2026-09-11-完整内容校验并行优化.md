# 2026-09-11｜完整内容校验并行优化

- 目标：缩短本机仓库与移动盘之间约五分钟的完整内容校验，同时继续逐字节读取两端、保持 SHA-256、来源只读和并发变化 fail-closed。
- 类型：feature。
- 状态：实现、产品回归、真实 C/H 隔离性能复测、便携包重建和 EXE 烟测均已完成，日志已封存。
- 日志索引：[工作日志 MOC](./MOC_工作日志.md)。

## 诊断与决定

- 原实现对每个同大小文件先完整哈希来源，再完整哈希目标，两块独立磁盘的读取时间直接相加。隔离基线中，5000×4 KiB、256×1 MiB、8×64 MiB 三组完整校验中位耗时分别为 31.162、1.978、1.195 秒。
- 完整校验不能用大小、mtime、ctime 或旧摘要代替当前内容读取；Windows NTFS 与 exFAT 都能出现内容已变但现有完整快照不变的情况。因此不引入抽样、不跳过任一端，也不改变 SHA-256 语义。
- 两端卷身份不同才用固定两个 worker，同时哈希同一文件的来源和目标；同卷仍顺序读取，避免机械盘或同一设备内的并发寻道。每端始终最多一个读取者，不跨文件并发。
- worker 只更新受锁保护的内部字节数；公开进度由分析线程汇总为本文件两端总字节并发出。任一端失败或取消会通知另一端停止并等待两个 worker 退出；汇合后再次复核两端完整快照。
- 深度校验在读取内容前，以一个事务退役当前和反向方向的旧等价记录；相同文件逐项重新建立记录。取消后仅已完成项目可复用，未完成项目不会被旧缓存误判。
- SQLite 继续使用旧版兼容的五列表结构。大小写等价路径由内存规范键归并；写事务用 `BEGIN IMMEDIATE` 与 `PRAGMA data_version` 拒绝陈旧连接写入，避免另一任务较新的失效结果被旧分析覆盖。GUI、CLI 预览和同进程引擎也统一执行单任务互斥。

## 文件变更

- [engine.py](../../obmanage/engine.py)增加异卷双端并行哈希、单调聚合进度、worker 退出与最终双端复核，并强化深度校验的旧记录退役和进程内任务互斥。
- [store.py](../../obmanage/store.py)增加大小写规范记录管理、双向原子失效以及跨连接陈旧写拒绝，保持旧五列表兼容。
- [app.py](../../obmanage/app.py)让命令行只读预览与 GUI 共用实例锁。
- [test_engine.py](../../tests/test_engine.py)、[test_store.py](../../tests/test_store.py)和[test_app.py](../../tests/test_app.py)覆盖并行成功/错误/取消、进度线程、无残留 worker、深度缓存失效、大小写变体、事务回滚、跨连接竞态和实例锁。
- [README](../../README.md)、[使用指南](../../docs/使用指南.md)与界面说明明确“异卷并行但仍是全量校验”；版本和 manifest 升至 1.2.3。

## 实际验证

- 最终源码在 C: NTFS 来源/状态与 H: exFAT 目标的隔离目录完成三组预热和各三轮完整校验，全部无错误、无差异、复制零字节并精确跳过全部文件；所有临时目录已清理，未读取或执行真实用户仓库。
- 最终中位耗时：5000×4 KiB 为 16.136 秒（1.931×，降低 48.2%）；256×1 MiB 为 0.975 秒（2.029×，降低 50.7%）；8×64 MiB 为 0.425 秒（2.810×，降低 64.4%）。这些数字包含深度记录退役、跨任务互斥与逐文件重新保存成本。
- 独立线程跟踪确认 C/H 每个文件对确实由两个 worker 重叠读取，最大并发为 2，摘要与计划一致。
- 153 项产品测试通过；记忆工具的 12 项独立测试及索引/格式检查通过。
- 旧 EXE 未运行且构建目标确认位于工作区后，使用项目构建脚本完成 1.2.3 便携包；新 `ObManage.exe --smoke-test` 退出码为 0，截图目视正常后连同隔离状态目录一起清理，烟测结束无残留进程。

## 结果与后续

1.2.3 源码和便携程序均已验证。不同卷的完整内容校验仍读取两端全部字节，但墙钟耗时从两端串行相加降为更接近较慢一端。Windows 内核中的单次磁盘读取若永久不返回，Python worker 无法强制终止该系统调用；这是保留安全汇合语义下的设备 I/O 边界。
