# 仓库统计全文件画像

## 目标

把原本偏向 Markdown 的仓库统计扩展为仓库整体画像，既能查看全部仓库汇总和逐仓库容量，也能识别视频、PDF、Word 等常见文件类型并清晰展示。

## 决策与改动

- 继续沿用严格只读遍历边界，但把统计口径扩展为所有安全观察到的普通文件；逐仓库保存文件总数、逻辑字节总和、文件夹数、Markdown 子集和文件类型构成。
- 文件类型按扩展名归入 Markdown、Obsidian 画布、图片、视频、音频、PDF、Word、Excel、PowerPoint、电子书、压缩包、代码、数据、文本、字体和其他文件。无法识别或无扩展名的普通文件仍计入总数与大小，并进入“其他文件”。
- 所有已计入文件都在最终目录复核中比较内容敏感状态；非 Markdown 在扫描期间发生大小、时间或身份变化时也会把结果标为不完整。
- 页面顶部显示全部仓库、文件、内容总大小、Markdown、字符和警告；逐仓库表显示文件、文件夹、大小和 Markdown；文件类型表显示扩展名、数量、大小和占比，并可随一个或多个仓库选择切换范围。
- 内容总大小明确表示普通文件逻辑字节之和，不冒充 NTFS 实际分配空间；`.obsidian`、默认关闭的根级 `.trash`、嵌套子仓库和应用事务目录仍按既有边界排除。

## 实际验证

- 统计服务、页面与多尺寸布局定向回归：`44 passed in 9.50s`。
- 最终完整回归：`341 passed in 57.07s`。
- 980×620、1140×920 与 2560×1440 下，逐仓库表和文件类型表均填满可用宽度且无横向滚动；长仓库路径保留悬停访问。
- 记忆索引已刷新，记忆检查通过 37 个 Markdown 页面。
- `tools/build.py` 成功生成 `dist/ObManage/ObManage.exe` 与平铺根目录的 `dist/ObManage.zip`；冻结 EXE 隔离状态烟测退出码为 0，并生成 78,055 字节截图。
- ZIP 共 236 个条目，根层含 `ObManage.exe`、`_internal/`、`使用说明.md`、`THIRD_PARTY_NOTICES.md` 和 `licenses/`，不含 `ObManage/ObManage.exe`；大小 50,771,154 字节，SHA-256 为 `C92C86EE32D2F1781494AF2018171B42290991415EF4A4FBA76099C5381DE3C6`。
