# 直接同步与目标会话

本地与远端 main 起点均为 d0ae764。保留原未跟踪材料。需求覆盖直接同步、目标列表和按仓库管理 Obsidian 会话。实现见 [ADR-012](../决策/ADR-012-直接同步与目标会话.md)。

镜像与无视频备份在各自 worker 中生成本轮分析，确认方向、完整路径和删除范围后交给原引擎。空有效来源会在同一次确认中明确提示清空后果，定时遇到空源暂停。增量继续扫描配对并逐仓库选择方向，差异详情可按需查看。回收站、归档及事务处理的业务范围保持原有约束。

`.comSync` 独立配置集合根，支持全部、当前运行、最新创建和文本搜索。隐藏选择移除，刷新核验目录身份。工作流冻结目标，跳过预检查一致的仓库，关闭实际写入目标的窗口，再分析窗口关闭保存的配置。一次最终确认绑定新计划。执行前、暂存完成及逐目标提交前保留会话复核。已关闭会话按本轮结果恢复，单目标显式打开独立判断。

## Windows 实机

在 Windows 11 上为 Obsidian 1.10.6 使用独立桌面、应用配置、临时仓库和 ObManage 状态。A、B、C 共享主进程，B 有两个真实窗口（主窗口和弹出窗口）。选中 B、C 后，预检查一致的 C 和未选 A 保留原窗口及进程身份，B 的两个窗口正常关闭。取消分支保留目标数据且无事务，确认分支只写入 B 的选定内容并生成一笔部署事务。两条分支均观察到 Obsidian 保存窗口配置，并按精确登记 ID 发出一次恢复打开请求。真实用户配置及会话保持原状。

取消和成功分支均观察到 B 的主窗口和弹出窗口实际恢复，重复打开请求被抑制。隔离探测用带私有配置参数的原生 Obsidian 进程接收 URI；系统默认 URI 分派未用于实测。实机观察到窗口配置保存，未观察到 `workspace.json` 内容变化，关闭时修改该文件由回归测试注入覆盖。运行枚举覆盖应用所在原生桌面，其他登录会话和原生桌面未纳入。

## 回归

最终全量测试 885 项通过，无失败或跳过。回归注入了窗口关闭时保存工作区、目标重开、已确认计划失效、部分关闭后的取消与恢复、等待确认时定时到点和空来源风险。测试使用临时仓库和独立状态目录。

## 包与界面

源码界面使用演示数据检查 980×620、1140×920 和大窗口，核对表格适配、完整路径和同步入口。全量回归曾在小窗口复现增量页长错误文本扩大页面宽度，修正后保留完整文本的选择和悬停，增量及布局专项 35 项通过。

基于最终程序源码运行 `tools/build.py`。ZIP 平铺根结构、CRC、根层说明和许可证校验通过，236 项共 51,064,866 字节，SHA-256 为 `191d258553dec3d2f11c402678f59b78c2130b8b842b2672e77a466d33716755`。解压 EXE 的镜像、备份、增量和配置同步四页原生启动通过，六个新工作流模块均在冻结包中，镜像深度预览保持隔离仓库内容。

阶段确认期间保持工作槽，定时到期消费本轮。复核发现暂存清单校验与目录切换之间仍可能重开目标，补充切换前屏障和自动回退的相关会话检查。发生占用时保留认证事务供处理。首轮构建遇到旧输出根目录句柄占用，构建改在工作区内暂存，核验目标路径后发布程序与 ZIP；保留原干净 PATH。
