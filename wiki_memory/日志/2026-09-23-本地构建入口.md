# 本地构建入口

## 目标与实现

用户更新源码后，本机 `dist/` 仍是旧产物；它被 Git 忽略，需要从拉取后的工作树重新打包。原有根目录 `buildStart.cmd` 为空。

- 填写 [`buildStart.cmd`](../../buildStart.cmd)：从脚本所在目录运行，检查本地 `.venv`，按用户新增授权精确匹配并强制结束本工作区 `dist/ObManage/ObManage.exe`，等待退出后调用现有 [`tools/build.py`](../../tools/build.py)。失败返回非零状态，不结束其他位置的副本。
- [README](../../README.md) 改用这个入口说明本地构建；[打包运维知识](../知识/运维/Windows打包与排障.md)记录脚本与 `git pull` 后仍需重建的关系。
- [工程约定](../../AGENTS.md) 记录后续打包可精确终止旧实例的授权及处理中任务可能中断的影响。

## 验证与结果

- 从仓库外工作目录调用最终 `buildStart.cmd` 成功；入口先结束本轮以隔离状态启动的旧版测试实例，再调用现有 `tools/build.py`。构建返回码 0，未启动真实仓库任务。
- 新 `dist/ObManage/ObManage.exe` 通过 `--smoke-test` 隔离状态启动并正常退出，返回码 0，生成非空截图。
