# comSync 组件同步整合

## 目标与规则

以原 .obsidian同步 三步流程整合模板套件和 .Templater，最终为 .comSync。用户确认最新仓库按根文件夹创建时间选择，排除来源，同时间并列选择。目录沿用现有 File/Templater、File/Note、File/Attachment 约定，界面组件名称带点；File 包含一次 Templater 内容同步，只补齐另两个目录而不复制笔记附件。

## 实施

- 版本 2.5.0，导航从九页减为七页，仓库镜像仍固定第一页。五组件位于来源卡片，随宽度换行；独立组件名、路径悬停、目录预览及单次目标数量保持清楚。常规窗口可见底部确认和执行，小窗通过纵向滚动到达。
- 创建时间只在本页扫描 worker/来源集合读取中附加，不改变其他页面。最新按钮替换勾选并清空搜索，不自动同步；时间缺失禁用且显示问题。
- File 编译为三个互不重叠的限定目标；Templater 去重，已有 Note/Attachment 只核验目录身份，零内容读取/替换/删除且不进入恢复授权；缺少时通过原事务创建空目录，内容或身份变化使陈旧计划/撤销失败并保留现场。
- 设置迁移优先原选中页面，其次配置、套件、Templater；原命名空间保留，新 comsync 设置不被覆盖。原三类及未知旧标签部署批次集中展示、撤销/确认；全局恢复门禁和单任务 worker 不变。历史日志旧功能保留可筛选标签。
- 公开指南/README 更新组件路径映射、流程、创建时间语义和恢复边界，截图仅使用演示数据。

## 验证

- 全量 pytest：511 项通过，93.17 秒。包括新旧目标混合多组件执行、源字节/mtime/身份不变、Templater 仅一次、Note/Attachment/其他 File 内容保留、独立组件、缺少来源、非目录/链接冲突、创建时间并列与缺失。
- 故障覆盖预备失败、提交失败/取消、晚出现目录、来源内容变化、卷变化、持久撤销与确认；已创建目录有新增用户内容时拒绝撤销。真实 Qt worker 完成扫描→最新选择→预览→配置与 File 同步→撤销，日志归属 comsync。
- 七页三尺寸布局回归通过；额外原生截图为 980×620、1140×920、实际最大化 2560×1417。表格列填满宽度、完整路径悬停、确认与底部操作可达。
- 开发写操作仅在隔离临时目录，没有同步真实用户仓库。
