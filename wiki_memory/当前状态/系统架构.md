# 系统架构

## 模块与数据流

| 模块 | 职责 / 关系 |
| --- | --- |
| [models.py](../../obmanage/models.py) | `PlanItem`、`SyncPlan`、`Progress`、`SyncResult`，UI 和引擎共享的数据契约 |
| [paths.py](../../obmanage/paths.py) | 长路径、重解析点拒绝、包含关系、磁盘/目录身份和操作前复核 |
| [store.py](../../obmanage/store.py) | SQLite 文件等价记录及临时文件所有权；按有序根路径和磁盘身份隔离 |
| [engine.py](../../obmanage/engine.py) | `analyze()` 生成带完整扫描上下文的计划，`execute()` 复核后写接收方 |
| [settings.py](../../obmanage/settings.py) | 本机/移动盘固定端点映射为有效 source/target，原子保存配置，方向迁移 |
| [scheduler.py](../../obmanage/scheduler.py) | 本地时间间隔/每日调度；忙时消费到期事件，不积压任务 |
| [ui.py](../../obmanage/ui.py) | 主线程管理控件和方向确认，`SyncWorker(QThread)` 在工作线程创建引擎 |
| [app.py](../../obmanage/app.py) | 启动、日志、同状态目录的 `QLockFile` 单实例；CLI 只提供预览 |

手动流程：固定端点 → 选择方向 → 分析完整目录并比较 → `SyncPlan` 预览 → 勾选本轮确认 → 复核快照/磁盘 → 创建与复制 → 复核 → 删除目标多余项目 → 结束复核。完整内容校验对不同卷上的同一文件同时读取两端，各卷最多一个 worker；普通快速分析仍复用精确匹配的等价记录。

定时流程复用相同引擎，绑定有效有序路径；空源清空要求暂停定时并转为人工处理。切方向或路径会使旧预览、确认和定时绑定失效。

## 状态与部署

程序数据默认在 `%LOCALAPPDATA%/ObManage`：`settings.json`、`baselines.sqlite3`、`ui.log`、`obmanage.log`。引擎拒绝把数据目录放在任一同步根内。预览也会保存已完成的内容校验记录，但不修改两侧仓库。GUI 与 CLI 预览共用实例锁，同进程的引擎实例也共享任务锁；SQLite 写入另用 data version 检查拒绝陈旧连接提交。

依赖固定在[requirements](../../requirements.txt)和[开发依赖](../../requirements-dev.txt)。普通 GIL 版 Python 3.14、PySide6 和 SQLite；PyInstaller `onedir` 输出 EXE 及 `_internal`，由[manifest](../../windows.manifest)声明长路径和高 DPI。
