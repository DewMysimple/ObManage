# 系统架构

2.5.2：ZIP 清单及只读摘要阶段复用有界祖先检查，实际压缩读取仍逐文件检查完整路径链；同卷 ≤64 KiB 暂存直接运行在既有任务线程，大文件/异卷保留单来源 worker。反向基线不重复持久化同一等价结论；部署 JSON 紧凑编码，认证和落盘语义不变。见[性能日志](../日志/2026-09-28-文件处理性能优化.md)。


## 应用壳与任务

[`pages/registry.py`](../../obmanage/pages/registry.py) 以静态顺序注册七页，保证冻结包可发现全部实现；[`ui.py`](../../obmanage/ui.py) 创建固定左侧导航、镜像页及六个可滚动管理页。镜像保留历史验证过的 `SyncWorker(QThread)`；仓库增量、备份和其他管理页通过 [`FeatureWorker`](../../obmanage/tasking.py) 运行无 Qt 服务。两类 worker 共用一个应用任务槽，页面可切换，但不会并发执行两个任务。

全局忙碌状态同时禁用相关页面写入口；只有底层实际接收取消事件的任务才显示全局取消。有部署 journal 或升级前遗留回收站隔离批次待处理，或记录无法安全枚举时，恢复门禁暂停手动/定时镜像和所有新部署、清理；导航提供待恢复入口，各事务页面仍可处理自己的撤销、恢复和确认。定时任务忙碌或被恢复门禁阻止时消费本轮到期事件，不累计补跑。

所有路径选择共用 [`VaultSelection`](../../obmanage/pages/vault_selection.py) 适配器，并占用相同的 `FeatureWorker` 任务槽；不会另起无管理线程。列表包含已登记及范围内仓库，运行识别使用 [`running_vaults.py`](../../obmanage/management/running_vaults.py) 枚举真实 Obsidian 窗口并匹配唯一完整仓库名称；重复名称和未知标题不会猜测路径。单一无问题结果可由识别动作直接填入，多结果明确选择；输入变更沿用旧预览与确认失效机制。

`.comSync` 通过原 DistributionPage 流程统一管理五组件；[comsync.py](../../obmanage/management/comsync.py)解析限定范围并读取创建时间，来源列表和集合扫描都在已有 worker 内附加时间元数据。最新选择只影响显式目标勾选，不自动执行。`.File` 展开为一次 File/Templater 内容部署及两个 directory-only 意图；已有 Note/Attachment 只做卷/身份复核且不进入恢复授权，缺少的空目录使用原暂存/提交/撤销事务。配置与完整模板仍保持全内容哈希。

部署恢复新增 `RecoveryPreview` 和 `resolved` 终态：只读检查绑定修订及内容；保全回退先持久化当前清单，再移动当前目录并恢复原备份。`resolve` 仅更新认证记录，原目录与所有副本零写；可选清理失败保持已结束状态。详见 [ADR-010](../决策/ADR-010-事务结束与备份清理解耦.md)。

## 服务层

| 模块 | 职责 / 关系 |
| --- | --- |
| [management/models.py](../../obmanage/management/models.py) | 仓库目录、问题和统计模型 |
| [management/catalog.py](../../obmanage/management/catalog.py) | 真实仓库发现、全部登记来源候选与独立的打开状态读取；精确根校验可不递归笔记 |
| [management/incremental.py](../../obmanage/management/incremental.py) | 按相对路径配对、隐藏一致项、逐仓库选来源、整批预复核及串行镜像 |
| [management/statistics.py](../../obmanage/management/statistics.py) | 严格只读、流式 UTF-8 Markdown 统计 |
| [management/deployment.py](../../obmanage/management/deployment.py) | 限定子树计划、全目标准备、提交、回滚和清理 |
| [management/journal.py](../../obmanage/management/journal.py) | 部署批次、授权锚点、完整性认证和原子更新 |
| [management/trash.py](../../obmanage/management/trash.py) | 根级 `.trash` 完整预览、直接清理及 2.0.0 遗留隔离兼容 |
| [engine.py](../../obmanage/engine.py) | 完整或排除视频的单向镜像扫描、增量内容判断和只写目标执行 |
| [reading.py](../../obmanage/reading.py) | 大小自适应缓冲、完整流式 SHA-256、单轮只读相邻祖先检查；不用于写入路径授权 |
| [copying.py](../../obmanage/copying.py) | 全部运行期复制路径共用的块复制、短写处理及单次来源 SHA-256 |
| [file_types.py](../../obmanage/file_types.py) | 统计与无视频备份共享的视频扩展名规则；保留 `.ts` 作为普通代码文件 |
| [paths.py](../../obmanage/paths.py) | 长路径、最终路径、包含关系、重解析点和物理身份复核 |

统计只读数据流：集合根 → 仓库发现 → 嵌套仓库边界 → 逐目录安全验证 → 全部普通文件的数量、逻辑大小和扩展名分类 → 可选的最多四路 Markdown 内容读取 → 文件及目录最终复核 → 全局/逐仓库/类型汇总及显式问题。元数据模式仍统计全部文件画像，但不打开 Markdown 正文。

仓库备份数据流：固定笔记本/移动硬盘端点和本轮方向 → profile 隔离的两端扫描 → 视频扩展名从两端管理清单中排除并形成可见 `exclude` 项 → 非视频 SHA-256/基线比较 → 方向确认 → 目标暂存、写后 SHA-256、替换 → 非视频删除。目标视频及其祖先目录始终留在目标，视频内容不哈希；完整镜像不使用这个过滤 profile。复制期逐文件保持具体路径链和快照复核，完整卷/根检查最多合并 16 个文件或 250 ms，并在删除屏障强制执行。来源和目标卷不同时，一个专用来源写 worker 最多提前准备下一份已登记目标临时文件，主执行线程同时复读当前临时文件；提交、SQLite、公开进度和删除仍保持单线程顺序。同卷不重叠读写。无删除任务把复制后的完整来源/目标复核直接作为最终屏障；有删除时仍在删除前后各完整复核一次。

部署数据流：来源/固定组件/显式目标 → 文件和目录预览 → 复核 Obsidian 占用、路径和卷 → 每目标同卷暂存 → 一次完整暂存树 SHA-256 → 全部准备屏障 → 目录改名提交 → 保留旧目标 backup → 撤销或确认清理。回收站数据流：仓库发现 → 精确根级 `.trash` 内容哈希清单 → 默认选择全部非空项 → 不可恢复确认 → 全部所选预览重扫屏障 → 按原清单直接删除 → 保留 `.trash` 根。执行期新增内容不进入删除授权；部分失败报告已删数量后要求重新扫描。

## ZIP 归档与日志

[archive 服务](../../obmanage/management/archive.py) 接收显式来源、输出文件和压缩级别，生成带内容摘要的清单。保存目录可为来源的上级但不能位于来源内部；操作只创建一个新文件，不镜像或删除已有输出。目标卷唯一临时文件经 ZIP 流式写入、全包 SHA-256/结构检查、来源重读和清单复核后独占发布，同名已有文件拒绝覆盖。复用路径、共享复制/读取、视频扩展名及持久恢复门禁；页面通过现有 FeatureWorker 运行。网盘联动仅在成功后按配置请求打开客户端，不访问云账号或推断上传完成。

[operation_log.py](../../obmanage/operation_log.py) 保存有功能、事件、状态和任务标识的 JSONL；兼容解析当前/上一份纯文本 UI 日志，并按实际副本数量去重。应用任务上下文独立于当前显示页面。[日志对话框](../../obmanage/pages/logs.py)组合时间段、功能、事件、任务、状态和关键词筛选，明确标注显示上限和读取问题。结构化日志当前文件加四份轮转历史，每份约 2 MB；完整保留记录参与筛选，显示最多 2,000 条，复制全部匹配项。

## 设置与持久状态

仓库增量数据流：两端集合根验证 → 只读发现 → 相对路径配对 → 单次比较生成双向计划（默认精确快照基线复用、可选完整内容校验）→ 隐藏一致项 → 用户逐仓库选择来源并确认 → 检查全局恢复状态和所选范围不重叠 → `SyncEngine.validate_plan` 复核全部所选仓库 → 每仓库继续独立执行期复核、校验复制和删除。失败或取消停止后续，结果保留逐仓库实际数量；不是整批事务。来源选择不持久化，设置只保存两端路径。详见 [ADR-009](../决策/ADR-009-逐仓库人工方向增量.md)。

[`settings.py`](../../obmanage/settings.py) 保存 schema v2 文档：`ui.selected_page`、`features.mirror` 和各管理页命名空间。旧分发页面选择迁移到 `comsync`，优先承接当时选中的旧页面设置，保留原命名空间；新设置存在时不重复迁移。所有历史部署批次由统一页面恢复。旧平面镜像设置读入后兼容运行，第一次写 v2 时保留一次 v1 备份；单个功能字段损坏不清空其他功能。

程序数据默认位于 `%LOCALAPPDATA%/ObManage`，包括按页面命名空间保存的设置、完整镜像与无视频备份相互隔离的 SQLite 基线、部署 journal/授权/密钥、回收站跨进程锁、升级前遗留回收站 journal/隔离/密钥及日志。新回收站清理不创建隔离持久状态。部署恢复目录位于各目标卷的仓库根附近，使用 `.obmanage-deploy-*` 保留命名空间；仓库发现、统计和镜像不进入这些目录。恢复记录与目录身份绑定并使用系统级跨进程锁，但完整性认证不替代操作系统账户权限，具体边界见[已知问题](./已知问题.md)。

## 运行与打包

依赖以 requirements 文件为准：普通 GIL Python 3.14、PySide6、SQLite 和标准库；部署、回收站与镜像引擎不依赖 Qt。GUI 用状态目录 `QLockFile` 保证单实例，并用同一路径派生的 `QLocalServer` 接收重复启动请求，使已有窗口恢复、置顶并激活。PyInstaller `onedir` 输出 EXE 及 `_internal`，由 [manifest](../../windows.manifest) 声明长路径和高 DPI；构建脚本使用干净子进程 PATH。
