# 当前约束

## 产品和执行边界

- 一次只运行一个方向：来源仓库只读；复制、覆盖、改名和删除仅落在接收方。正常镜像包含删除目标独有文件及目录；不以修改时间“谁新谁赢”。
- 手动操作先分析，再确认本轮方向后执行。删除语义必须在 UI 中明确指向接收方；缩减重复文案不得隐藏实际修改位置或取消此确认。
- 同路径、互相包含、目标盘根、重解析点及文件/目录冲突都不能执行。状态目录不得位于任一仓库中。
- 扫描失败、旧计划、取消、设备变化或复制失败必须停止后续删除。普通更新使用目标盘临时文件、校验及替换；已完成文件不回滚。
- 空来源若会清空接收方，必须手动确认；定时暂停处理。运行中不准改变方向和端点，到点不累积任务。
- 第一版按整个文件增量，不做视频内部分块同步、自动合并或历史备份。深度校验必须绕过两个方向的元数据缓存。

来源：[engine.py](../../obmanage/engine.py)、[paths.py](../../obmanage/paths.py)、[settings.py](../../obmanage/settings.py)、[UI 方向回归测试](../../tests/test_direction_ui.py)、[往返来源保护测试](../../tests/test_roundtrip.py)。

## 协作和发布

- 用户要求：**每次完整对话产生的修改都要提交并推送**。结束前检查相关 diff、运行必要验证、更新记忆、提交并推送，核对远端；失败如实说明，不绕过错误或宣称完成。
- 保持顶部精简、差异表四列“操作 / 实际修改位置 / 大小 / 说明”，不恢复重复“相对路径”列。表格应随可视宽度填满并显示列分隔线；此布局已实现并经窗口/最大化验证，后续改动需保留[布局回归](../../tests/test_ui_layout.py)覆盖的行为。
- 真实仓库验收先做只读预览；本工程开发测试在临时目录完成，不能为了测试触发真实数据镜像。
- 提交源码与必要文档；不提交 `.venv/`、`build/`、`dist/`、私有预览、运行状态数据库和本机快捷方式。
- 记忆只写已授权事实和有依据结论，猜想用 `proposed`。公开 README/记忆不保留用户仓库内容、机器用户名或私有绝对路径。
