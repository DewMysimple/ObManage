# 当前约束

## 共用产品边界

- 一个功能一个页面，仓库镜像固定为第一页。所有页面共用应用任务槽；运行中可切页但不能启动第二任务，只有真实可取消任务才显示取消入口。
- GUI 按状态目录保持单实例；再次打开同一 `ObManage.exe` 时必须通过本地 IPC 让已有窗口恢复、置顶并激活，而不是弹出第二个窗口。
- 真实仓库开发验收先做只读预览。本工程自动测试必须使用隔离临时目录，不以 UI/文档授权推导执行真实镜像、部署或回收站清理。
- 仓库只由普通 `.obsidian` 标记确认；按物理身份去重，链接、目录联接、重解析点、特殊项、越界、相等/包含路径和不可靠身份均拒绝或形成显式问题。
- 长路径必须可完整悬停；回收站页不提供复制所选路径功能。分发目标默认不选，回收站扫描后默认选择全部非空项。输入、方向、组件、路径、目标或页面上下文改变后，旧计划和破坏性确认失效。删除位置和数量始终明确。
- 操作日志界面按新到旧展示，打开窗口及新增记录后都停在顶部；磁盘中的日志文件仍按追加顺序保存。复制期总体进度必须单调，顶部相同状态不得随每个文件重复重绘，非终态管理任务进度按约 100 ms 合并。统计必须覆盖全部安全观察到的普通文件及其逻辑大小和扩展名类型；未知类型进入“其他文件”。提速不能以跳过正文、弱化 UTF-8 精确计数、路径身份复核或变化可见性为代价。
- 待恢复或不可安全读取的部署事务及升级前遗留回收站隔离批次会阻止所有新的写操作和定时镜像，只读统计及对应恢复动作仍可用；不得让新批次遮住旧批次。

## 镜像

- 一次只运行一个方向：来源仓库只读，复制、覆盖、改名和删除仅落在本轮目标；不自动合并两端改动，不以时间“谁新谁赢”。
- 普通复制先写目标卷临时文件，关闭写句柄后重读并校验 SHA-256。异卷仅允许一个来源写 worker、最多提前暂存一个文件；当前文件校验完成后仍由主执行线程顺序提交，失败时汇合 worker 并按精确登记清理临时项。同卷读写保持串行。新增/更新失败、取消、旧计划、设备或来源变化必须停止后续删除；空来源清空目标额外人工确认，定时暂停或跳过。逐文件检查具体路径链和快照；完整卷/根身份复核最多间隔 16 个文件或 250 ms，长文件替换前及阶段屏障强制复核。没有删除项时复制后完整来源/目标复核即为最终屏障；确有删除时保留删除前后两轮完整复核。
- 保留完整内容校验、双卷并行读取、SQLite 精确基线、Windows 只读目标有限重试和现有 `SyncWorker(QThread)` 生命周期。
- `.obmanage-deploy-*` 恢复目录不进入扫描、复制或删除命名空间。

## 排除视频的仓库备份

- 仓库备份固定显示笔记本轻量仓库与移动硬盘完整仓库，每轮明确选择一个来源；来源只读，所有非视频新增、覆盖和删除只落在目标，不自动合并冲突。
- 视频按共享的大小写不敏感扩展名集合从两端管理清单排除。来源视频不哈希或复制，目标视频不覆盖或删除，目标中含排除视频的祖先目录不计划删除；`.ts` 保持普通文件语义，避免误排除 TypeScript。
- 排除视频必须由同步引擎及执行复核实施，不能仅过滤预览表。预览要显示每个排除路径；过滤模式和完整镜像的基线必须隔离，反向复用只能发生在同一模式内。
- 非视频复制、故障停止删除、空有效来源确认、路径/卷/身份复核、链接边界、只读目标处理和全局单任务/恢复门禁与完整镜像相同。切换方向、修改路径或离页会撤销确认。

## 部署与回收站

- 分发只写显式目标中的固定子树，来源只读。预览包含文件与目录的新增、更新、删除和跳过；所有目标以一次完整暂存树 SHA-256 校验后才开始提交，不在紧邻整树校验前重复读取每个暂存文件。
- 当前被 Obsidian 标记为打开的目标不得部署；占用配置读取不可靠时，需要额外确认目标均已关闭。确认保留并删除 backup 是独立的不可逆确认。
- 部署 journal 必须把所有可影响恢复、删除和父目录清理的字段绑定到创建授权或认证状态；事务目录名精确派生，不能按宽泛前后缀获得所有权。未知项零删除，部分清理只接受认证原清单的严格剩余子集。
- 回收站只处理真实仓库根级 `.trash`，扫描后默认选择全部非空项；不可恢复确认默认不勾选。执行前先完整复核全部所选预览，随后只按原清单直接删除并保留 `.trash` 根；新操作不创建隔离备份、journal 或认证密钥。
- 回收站直接清理不可撤销；权限错误、取消或执行期变化可能留下部分结果，必须报告实际删除数量和逻辑内容大小后要求重新扫描。执行期新出现的项目不纳入原删除授权。
- 部署及升级前遗留回收站记录继续使用 HMAC、身份锚点和跨进程锁防意外损坏、陈旧状态和孤立替换；不宣称抵御能够任意读写整个状态目录及仓库的同账户恶意进程。遗留批次不自动删除，处理完成前继续参与恢复门禁。

## 协作和发布

- 用户要求：**每次完整对话产生的修改都要提交并推送**。结束前检查相关 diff、运行必要验证、更新记忆、提交并推送，核对远端；失败如实说明。
- UI 变更检查 980×620、常规 1140×920 和大窗口；所有页面不得要求横向滚动，底部确认与恢复动作必须可通过纵向滚动到达。
- 提交源码与必要文档；不提交 `.venv/`、`build/`、`dist/`、真实仓库预览、运行数据库、凭据和本机配置。公开材料不记录私人绝对路径或旧工具文件名。
