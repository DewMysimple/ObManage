# ADR-010｜事务结束与备份清理解耦

2.6.0：独立“事务处理”页承载部署和旧版隔离恢复入口，复用既有控制器与全局任务槽；`.comSync` / `.Trash` 不再显示恢复区。已结束部署事务可明确清除全部认证副本及记录，或仅删除记录、保留副本原位；列表展示所有历史事务。删除记录使用认证 `discarded` 意图保证双文件删除中断后可重试，不重新阻塞。旧版隔离记录在全部副本清理后可删除。详见[本轮日志](../日志/2026-09-28-事务管理独立页面与清除.md)。

## 问题

旧恢复流程以当前目录必须匹配部署快照作为撤销和确认清理的共同条件。同步后正常写入也会阻止两者；撤销失败还会切换到旧确认接口不接受的状态，最终持续阻止全局新写入。

## 决策

- `.comSync` 统一接管历史标签，恢复区统一位于独立“事务处理”页。先检查所选事务，再明确选择保留现状或保全内容后回退，显示目标、冲突原因、保全路径和清理数量。
- `resolved` 表示用户接受当前状态、终止自动恢复。仅在认证有效、授权范围合法、状态目录独立及跨进程锁持有时更新 journal，不更改来源、目标或任何事务副本，不要求磁盘在线或当前内容匹配原快照。它不意味着同步成功或缺失目标已恢复。
- 保全回退绑定批次修订与本次全内容预览，全批预复核后逐目标再次复核。完整原备份及原部署目录身份必须可信。当前内容先改名至精确 `.rollback` 路径，保全清单写入认证 journal，再恢复旧子树；保全内容不获得自动删除授权。新建目录恢复为不存在，但其中后续内容同样保全。
- 回退意图先持久化。中途退出可继续恢复；已保全内容必须通过记录身份及清单验证。终态使用 `rolled_back_with_residuals` 保存可访问的副本位置。
- 结束后独立确认清理，只接受原授权内仍可验证的备份、暂存与普通回退隔离内容，不读取或改动当前限定子树；完整预复核、陈旧预览拒绝、逐树写前复核与部分删除重试继续保留。失败保持 `resolved`，不重新阻塞其他任务。回退保全副本不自动删除，仅在独立事务页重新检查并明确确认清除全部副本时才删除。
- 已结束事务不能再自动回退覆盖后续任务；已结束的保留副本仍可在列表检查并手动取回。待处理事务优先展示，每个未处理批次仍单独参与全局门禁。
- 认证损坏仍拒绝绕过；升级前回收站遗留隔离批次的语义不变。所有执行测试使用临时目录，开发不擅自结束真实用户事务。
