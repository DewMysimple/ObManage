# ADR-010｜事务结束与备份清理解耦

2.7.1 用户要求前台仅“确认完成”和“确认回退”。完成一次确认后先结束所选待处理部署，再清理本批全部可清理副本和记录；底层两阶段语义保留，失败不重新阻塞，其他待处理部署不自动结束。见[本轮日志](../日志/2026-11-02-comSync批量预览与事务简化.md)。

2.6.3：清除改为整批操作，先在全局后台任务槽只读检查全部已结束部署及隔离事务，再确认一次清除副本、事务目录和持久路径记录；副本已清理的历史记录同批移除。清理完成后列表和路径详情清空，重启不再出现。待处理部署先结束或回退；失败项保留记录供重试，确认后新增事务不扩大本批范围。见[批量清理日志](../日志/2026-10-07-事务彻底批量清理.md)。

2.6.2：事务处理使用同一个列表管理全部部署与隔离事务，不按版本分区。进入页面、换事务或刷新后自动检查；保留现状直接结束，回退和清除各确认一次。清除只有“清除副本和记录”，全部认证副本删除后才移除记录；失败或中断保留记录供重试。隔离副本及记录在同一进程锁和跨进程锁内清除。见[统一列表日志](../日志/2026-10-07-事务统一列表与成套清除.md)。

## 问题

旧恢复流程以当前目录必须匹配部署快照作为撤销和确认清理的共同条件。同步后正常写入也会阻止两者；撤销失败还会切换到旧确认接口不接受的状态，最终持续阻止全局新写入。

## 决策

- 独立“事务处理”页接管历史部署标签与遗留回收站记录。所选事务自动后台检查，手动入口为“确认完成”和“确认回退”。完整路径和方案按需展开。左下角保留操作日志入口，恢复门禁和相应操作处的提示继续生效。
- `resolved` 表示用户接受当前状态、终止自动恢复。仅在认证有效、授权范围合法、状态目录独立及跨进程锁持有时更新 journal，不更改来源、目标或任何事务副本，不要求磁盘在线或当前内容匹配原快照。它不意味着同步成功或缺失目标已恢复。
- 保全回退绑定批次修订与本次全内容预览，全批预复核后逐目标再次复核。完整原备份及原部署目录身份必须可信。保全清单写入认证 journal，在目标卷暂存、核验并原子切换，恢复中央备份时持久记录新暂存身份以供中断续行。当前内容保全到程序备份目录，原本不存在的子树恢复为不存在。
- 回退意图先持久化。中途退出可继续恢复；已保全内容必须通过记录身份及清单验证。终态使用 `rolled_back_with_residuals` 保存可访问的副本位置。
- 完成操作在同一次确认内先结束再清理，只接受原授权内仍可验证的备份、暂存与回退保全内容，不读取或改动当前限定子树；完整预复核、陈旧预览拒绝、逐树写前复核与部分删除重试继续保留。失败保持 `resolved`，不重新阻塞其他任务。
- 部署备份及回退保全副本集中在应用状态目录的 `backups`。旧批次只从认证记录指明且仍能核验的同卷位置迁入。程序备份路径从批次与目标编号派生，准备与完成状态和目录身份写入认证 journal；集中副本完整校验并登记后才清理本地旧位置，清理失败可重试。
- 自动清理在“事务处理”页显式设置，关闭为默认，开启时接受 1–36500 天。应用启动及运行期间检查到期的成功同步和已结束部署备份。通过核验的回退保全副本也受期限设置约束，清理后相应旧版本无法再用于恢复。中断或需要异常恢复的部署、不可核验的副本以及升级前回收站隔离批次不参加到期清理。
- 已结束事务不能再自动回退覆盖后续任务；已结束的保留副本仍可在列表检查并手动取回。待处理事务优先展示，每个未处理批次仍单独参与全局门禁。
- 部署与隔离事务使用同一个选择列表和清除按钮，不按版本分区。用户要求副本和记录成套清除，移除仅删除记录的部署接口；全部副本已清除后才删除认证记录。隔离清除在同一进程锁及跨进程锁内完成副本与记录两阶段操作，部分失败保留记录供重试。
- 认证损坏仍拒绝绕过；升级前回收站遗留隔离批次的语义不变。所有执行测试使用临时目录，开发不擅自结束真实用户事务。
- “确认完成”作用于所选待处理部署及整批可清理事务，包含全部已结束部署与隔离记录；统一只读预检后确认一次。隔离预览绑定认证记录摘要，执行前在双锁内复核；新增事务不自动进入已确认范围。副本此前已删除的历史记录也成套移除；失败按实际清除数量报告，剩余记录可重试。仅所选待处理部署由本次完成操作结束，其他待处理部署不自动纳入。
