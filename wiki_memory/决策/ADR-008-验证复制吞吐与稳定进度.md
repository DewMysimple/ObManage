# ADR-008：验证复制吞吐与稳定进度

## 背景

仓库备份在复制 16,320 个文件、5.6 GB 时约耗时九分钟。受控的 600 个 4 KiB 文件基准进一步显示执行耗时 10.94 秒；剖析结果表明主要时间并非传输数据本身，而是每个小文件前后重复执行完整路径链和 Windows 卷序列号复核。复制、写后哈希和完成三个事件还会按文件切换，使管理页绕过阶段节流、顶部文字重绘且进度在总体字节和单文件字节之间回跳。

## 决策

1. [`copying.py`](../../obmanage/copying.py) 提供所有运行期复制路径共用的单次来源读取、短写处理和 SHA-256 计算。镜像、无视频备份、限定子树分发及升级前遗留隔离恢复使用同一实现。
2. 镜像与备份仍在目标同目录建立随机暂存文件，关闭写句柄后重新读取暂存副本并校验 SHA-256，再以 `os.replace` 提交。移除逐文件 `FlushFileBuffers`：它不能让包含目录项、SQLite 与整个批次的操作成为断电原子事务，却会把大量小文件变成逐次高延迟等待；持久 journal、设置和认证记录的 `fsync` 不受影响。
3. 每个实际来源/目标路径仍通过 `checked_child` 检查完整祖先链并复核文件快照。较昂贵的源卷、目标卷、仓库根和目标锚点组合复核最多间隔 16 个文件或 250 ms；长文件会在替换前触发时间边界复核，进入删除及完成屏障时强制复核。
4. 限定子树部署复制时核对来源摘要，随后在准备屏障以一次完整暂存树 SHA-256 清单验证所有目标字节；删除紧邻其前、内容相同的逐文件目标哈希，避免连续读取同一暂存文件两遍。提交边界用于确认暂存树未被并发改变的第二次整体验证、全目标准备屏障、原子目录切换、持久恢复和提交后验证保持不变。
5. 镜像复制与写后校验各占当前文件逻辑进度的一部分，使全轮完成字节单调递增。`FeatureWorker` 不再因 `copy/hash/copied` 阶段变化绕过节流，非终态界面事件最多每 100 ms 一次；相同状态文字和样式不重复设置，终态仍立即显示。
6. 来源和目标卷不同时，允许一个专用来源写 worker 最多提前暂存下一文件，主执行线程同时对当前暂存文件做完整写后 SHA-256；同卷保持串行，避免机械盘并发寻道。所有临时路径先持久登记，提交仍严格串行；失败或取消先汇合 worker，再按精确路径与身份清理，公开进度与 SQLite 只留在主执行线程。
7. 安全子路径检查可返回同次观察的文件快照，紧邻的预览比较复用该快照而不减少祖先链检查。基线发布与临时所有权撤销合并为一个 SQLite 事务。没有删除项时，复制后已经完成的来源全树与预期目标全树复核直接成为最终屏障；只有实际执行删除时才需要删除后的第二轮完整复核。无视频目标的保护目录查询改为沿当前路径祖先查集合，语义不变。

## 结果与边界

第一轮同机同数据基准由 10.94 秒降至 3.82 秒。2.1.2 最终代码在 600 个 4 KiB、无删除任务的五轮中位数为 3.43 秒，同物理盘串行分支也不依赖并发取得约 10% 的进一步缩短；异卷流水线的收益取决于两块实际介质能否真正并行，不能用同一物理盘伪装异卷的数字代替真实 H/C 盘结果。结构测试已证明下一来源写入与当前目标校验确实重叠；故障测试证明当前校验失败时下一暂存不会提交。复制仍是整文件级，单个超大文件速度仍受较慢磁盘、目标写入和写后完整读取限制。应用不宣称整个多文件任务对突然断电具有文件系统事务原子性；进程失败、取消、并发变化和后续删除屏障继续 fail closed。
