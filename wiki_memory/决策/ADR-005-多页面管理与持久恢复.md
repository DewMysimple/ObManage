# ADR-005｜多页面管理与持久恢复

> 本决策已由 [ADR-006](./ADR-006-多页面管理与回收站直接清理.md) 替代。以下内容保留为 2.0.0 的历史设计；当前回收站采用预览后直接清理，仅兼容处理升级前遗留隔离批次。

## 背景与决策

ObManage 不再只承载仓库镜像。应用采用静态功能注册和左侧导航，一个功能一个页面，仓库镜像固定为第一页；首批增加仓库统计、模板套件部署、Obsidian 配置分发、Templater 分发和回收站清理。旧版脚本只提供业务意图，硬编码路径、控制台确认、隐式全选、先删后拷和仅存在内存中的恢复状态不迁移。

统计保持严格只读。三类分发共用限定子树部署引擎：用户明确选择来源、组件和默认未选中的目标，预览文件与目录结构，全目标先暂存并校验，再提交；批次持久记录，可撤销或确认保留。回收站只识别真实仓库根级 `.trash`，先复制到应用状态目录、逐项校验，再清空仓库；隔离内容可恢复或经再次确认后永久清理。

所有页面共享应用级任务槽。任何部署或隔离批次未完成、待确认或记录无法安全读取时，应用进入恢复门禁：新的镜像、定时镜像、部署和回收站清理均被阻止，只读功能及对应恢复动作仍可用。左侧入口指向待恢复页面；离开页面会撤销本轮破坏性确认。

## 理由和影响

- 页面隔离让每类写入范围、确认语义和恢复状态保持清晰，同时共用仓库发现、线程和日志基础设施。
- 持久事务把崩溃后的选择从“猜测当前状态”改为“复核身份后撤销或确认”，代价是完成写操作后还要处理一个明确的恢复步骤。
- 恢复门禁优先保护撤销能力；即使待恢复批次与新任务看似无关，也先暂停所有新写入。统计仍可运行，但运行中的任一任务继续占用全局任务槽。
- 设置升级为版本化按功能命名空间的文档；镜像旧设置自动迁移并保留一次备份。

## 安全边界

持久记录使用独立密钥认证，恢复目录绑定创建时身份，跨进程写操作使用系统锁。它们用于拒绝损坏、孤立替换和范围漂移，不构成对已经能任意读写应用状态目录与仓库的同账户恶意程序的隔离。普通路径 API 也不能完全消除恶意进程在检查与操作之间替换 Windows 重解析点的极窄竞态；正常操作应关闭其他写入者，失败后保留恢复数据并重新复核。
