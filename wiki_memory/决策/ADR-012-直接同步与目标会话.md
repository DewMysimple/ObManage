# ADR-012｜直接同步与目标会话

仓库镜像和无视频备份的独立预览、完整内容校验均只读取仓库。随后点击同步即确认已展示的范围，由执行器实时复核两端后写入。直接启动手动同步则分析并弹窗一次。空有效来源清空目标始终需要手动确认。离页、改输入或退出撤销本轮尚未使用的绑定，定时镜像独立分析并跳过正忙的一轮。

页面快速预览以各端的一次目录清单生成可核对的差异。准备该预览的引擎在同步点击后重新采集完整清单。完整内容校验、默认引擎分析与增量批次保留自己的结束复核。只有删除且没有登记暂存时，写前复核与删除前复核处在同一阶段，使用同一次真实扫描。删除后仍完整检查两端。见[阶段对照](../日志/2026-11-26-镜像逐阶段遍历与删除复核合并.md)。

`.comSync` 启动同步时实时分析已勾选的组件和目标。目标窗口已关闭时，从本次分析封印实际写入子集。先前展示的请求、树快照、身份和变更完全相同，点击同步可直接执行。直接启动、计划已变或本轮关闭过窗口时，以最终计划确认一次。确认与执行期间均保持原任务槽。

`.comSync` 的集合根配置决定发现边界，范围和搜索只改变目标列表。创建时间按完整有效候选计算，同时间全部显示；当前运行使用完整登记候选和运行身份。隐藏勾选会消失并提示，刷新保留身份仍一致的可见人工勾选。任务启动时冻结路径、目录及卷绑定、组件、目标和单目标打开意图。

初步分析一致的仓库记录为本轮跳过。仅需写入的目标会话进入关闭过程，按窗口标识发出正常关闭消息并验证结果，关闭成功的仓库逐一记录。窗口保存后重新分析实际写入范围，复核来源、目标和目录身份，然后封印最终计划。执行沿用同卷暂存和事务切换，在写入前、全部暂存后、目录切换前复核会话。目标重新打开时，针对涉及该仓库的自动回退保留待处理记录。窗口关闭行为和进程模型见 [Microsoft Win32](https://learn.microsoft.com/en-us/windows/win32/learnwin32/closing-the-window)、[Electron](https://www.electronjs.org/docs/latest/tutorial/process-model)和 [Obsidian 弹出窗口](https://obsidian.md/help/User%20interface/Pop-out%20windows)。

成功、取消、失败后安全恢复的结果允许重新打开本轮关闭的原有仓库，略过已运行的目标。确认执行未完成、身份变化或记录不确定时，保留待处理原因。单目标的显式打开意图可用于同步成功或无需写入；打开请求和持久事务结果独立报告。

运行窗口枚举排除系统辅助窗口。GDI+ 通知窗口须同时匹配系统类名、由可执行文件名生成的标题、隐藏状态和无所有者条件。其余可能承载仓库的窗口继续按登记路径和窗口关系核验，无法确认是否涉及写入目标时停止同步。见[误拦截修复日志](../日志/2026-11-23-comSync会话核验误拦截.md)。
