# ADR-011｜任务内共享扫描与实时结束复核

2.8.2：同范围历史结果只在选择器展示。列表键区分集合、登记来源和转换，实际刷新仍走原后台任务。历史点选只有本轮完整发现、范围及仓库标记身份匹配后才填路径。写任务及相关事务变化清空展示记录，实时清单和执行授权仍各自生成。实测共享统计线程池收益低于采用门槛，保留按仓库建池。见[验收](../../docs/2.8.2-扫描与响应优化验收.md)。

2.8.1 精修：两端已知集合问题时提前返回，保留故障信息。正常批次以新 epoch 覆盖发现边界及内容清单，正反向可以共享同一份实时清单与同一预期的比较。每个方向保持独立的根绑定，全部末次复核通过后才发布执行授权。同次祖先链检查返回的叶状态可用于紧邻枚举的起点，保留枚举后查询。见[本轮日志](../日志/2026-11-06-增量异常快退与实时复核精修.md)。

用户明确要求减少多页面全仓库任务的重复发现、首次清单和初始化成本，保留所有执行安全屏障。采用无 Qt 的 `scanning` 基础模块；不建立跨任务可信清单、持久仓库索引或新的后台线程。

`ScanSession` 保存一个任务 epoch 内的目录观察，不保留 `DirEntry`。Windows 枚举元数据的 inode/device 不可靠，进入镜像清单前必须使用 `snapshot()` 的完整路径身份字段。发现、统计、镜像和无视频视图各自保留范围规则；父仓库镜像包含子仓库，统计则不重复计入。

增量先共享双端集合发现与初次清单，再逐仓库比较、由一次内容结论派生反向计划；单任务共用 SQLite 连接，逐文件提交和不同模式隔离不变。批次结束使用全新会话重新观察两端集合及全部清单，检查仓库配对、嵌套 marker、新增/删除和文件身份；两个方向分别复核根绑定后才标记有效。执行前全部所选预检与实际串行执行的既有检查仍独立发生。

统计共享发现元数据，保留精确 UTF-8、文件句柄及目录末次枚举。发现专用区域新增仓库或嵌套边界变化必须形成可见的不完整结果，不能继续显示完整状态。缓存命中不是安全复核；缺失、歧义、链接、不可读、取消或扫描中变化都不能变成可执行空清单。

基准和对照测试从固定旧提交只读加载独立模块。计量默认关闭，显式激活或 DEBUG 时仅聚合任务指标，不记录文件清单或私有路径。归档适配实测退化后撤回；归档、部署和回收站保留专用遍历及执行器，只共享诊断基础设施。

证据：[架构与性能](../../docs/扫描架构与性能优化.md)、[扫描核心](../../obmanage/scanning/session.py)、[集合采集](../../obmanage/scanning/collection.py)、[增量服务](../../obmanage/management/incremental.py)、[独立对照](../../tests/test_scanning_equivalence.py)、[增量故障矩阵](../../tests/test_scanning_incremental.py)。延续 [ADR-009](./ADR-009-逐仓库人工方向增量.md) 的用户方向与执行边界。
