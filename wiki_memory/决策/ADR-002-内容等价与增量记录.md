# ADR-002｜内容等价与增量记录

## 背景与决策

已有镜像中的大视频不应因为两个磁盘时间戳表示不同而重写。首次遇到同路径同大小文件，分别做 SHA-256，内容相同则逐文件保存已验证记录并跳过。之后分别比较两侧各自的完整快照，任一不匹配才重新判断；不要求 source.mtime 等于 target.mtime。

SQLite 主键为有序的规范路径、两侧磁盘身份生成的 pair_id 加相对路径。大小、纳秒修改时间、ctime、设备与文件身份均属于实际快照。反向记录只有在对调后两端快照都精确匹配时才复用，并写入当前方向记录。

深度校验在读取前以一个事务退役正反两个方向的旧记录，逐字节重新读取两端；校验相同的文件逐项建立新记录，取消后只复用已完成项。若两端属于不同卷，同一文件的两个 SHA-256 可由固定两个 worker 并行计算；同卷保持顺序，汇合后再次复核双端快照。SQLite 仍保持旧版五列表，Windows 大小写等价键由写入层原子归并；陈旧连接不能覆盖另一任务更新后的记录。

## 理由和影响

已完成哈希逐条提交，所以首次接管或深度校验取消后无需重读所有已验证文件。路径/卷/方向隔离避免错误复用；反向等价复用改善往返性能。完整确认仍必须读取两端全部字节，异卷并行只重叠两端时间，不把全量校验弱化为元数据或抽样检查。快速扫描仍依赖元数据，不等价于每次读取全部内容。
