# ADR-009｜逐仓库人工方向增量

## 背景与决策

用户在移动硬盘编辑 A 仓库、在电脑编辑 B 仓库，希望先列出双方对应仓库的差异，再逐仓库决定哪端为权威来源，最终让两端都保留所选版本。文件更多、更少或时间更新均不能代替人的来源判断。

新增独立工作台，镜像仍为第一页。复用真实 `.obsidian` 仓库发现，按两端集合根下大小写不敏感的相对路径配对；同名不同位置不自动配对，直接选择两个仓库根时以 `.` 对应。首个方向强制内容比较，反方向仅可复用当前已证明的等价记录；有差异及异常显示，完全一致隐藏并计数。

每行默认“暂不处理”，明确选择电脑或移动硬盘为源；两个方向的新增、更新、删除、完整目标位置均可查看。数量少的一端可作为来源。仅一端有仓库时，只允许选存在的一端复制到缺失位置；已存在但不具有有效仓库标记的对应目录禁止覆盖。父子嵌套仓库可查看，但同批不能选择任何相等或包含范围，防止一个目标覆盖另一来源。

执行先调用引擎只读预复核检查全部所选计划，任一预览陈旧则整批零写；通过后串行复用单仓库镜像执行，继续复核路径、卷、快照、来源和写后 SHA-256。失败或取消停止后续，已完成部分保留并显示逐仓库结果。单仓库内部不合并两端编辑，目标独有内容属于删除范围，未选仓库保持原样。

仓库集合扫描问题使整批 fail closed；单个计划异常不能选取。服务与 UI 都检查部署/遗留回收站恢复门禁，后台使用应用单任务槽。设置只持久化集合路径，来源选择和确认不跨重扫保存；改路径清除预览，改选择或离页撤销确认。工作台包含所有普通文件，不沿用备份页的无视频模式，不定时执行，不承诺多仓库原子事务。
