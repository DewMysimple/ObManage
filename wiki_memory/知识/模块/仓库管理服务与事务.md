# 仓库管理服务与事务

2.6.2：事务处理使用同一个列表管理全部部署与隔离事务，不按版本分区。进入页面、换事务或刷新后自动检查；保留现状直接结束，回退和清除各确认一次。清除只有“清除副本和记录”，全部认证副本删除后才移除记录；失败或中断保留记录供重试。隔离副本及记录在同一进程锁和跨进程锁内清除。见[统一列表日志](../../日志/2026-10-07-事务统一列表与成套清除.md)。

2.5.2：归档只读清单与来源复核使用 `ReadScope.observe` 共享有界祖先查询，叶子快照逐项读取，写入期完整路径链、ZIP 校验、来源重读与最终清单不省略。部署事务 JSON 改为紧凑编码单次写入，认证值、旧格式兼容及 fsync/原子替换不变。见[性能日志](../../日志/2026-09-28-文件处理性能优化.md)。


## 一句话结论

非镜像页面的 Qt 代码只编排输入、预览、确认和恢复；仓库发现、统计、限定子树部署、回收站直接清理及遗留隔离兼容均位于无 Qt 依赖的 [`management`](../../../obmanage/management/__init__.py) 服务层，并通过临时目录故障测试验证。

## 仓库发现与统计

[`catalog.py`](../../../obmanage/management/catalog.py) 只把带普通 `.obsidian` 目录的路径认作仓库，按物理身份去重，拒绝链接、重解析点和不可安全读取的边界。父仓库下的嵌套仓库作为独立仓库，不重复穿透统计；父仓库根级 `.trash` 视为已删除内容，里面残留的 `.obsidian` 不会成为统计或分发目标。应用自有 `.obmanage-deploy-*` 恢复目录是保留命名空间，发现、统计和镜像均不进入。

[`statistics.py`](../../../obmanage/management/statistics.py) 始终排除根级 `.obsidian`，默认排除根级 `.trash`，统计全部安全观察到的普通文件数量与逻辑字节，并按扩展名归入 Markdown、Obsidian 画布、图片、视频、音频、PDF、Word、Excel、PowerPoint、电子书、压缩包、代码、数据、文本、字体和其他文件。每个仓库保留独立类型构成，结果层可聚合全部或所选仓库；未知扩展名和无扩展名文件不会漏计。

Markdown 字符数按严格 UTF-8 码点流式读取；同目录共享一次紧邻读取前的路径链验证，最多四个文件并行读取，但每个文件句柄与当前路径仍独立复核身份、大小、时间 epoch。所有已计入的普通文件都以内容敏感状态参加最终目录稳定枚举，因此非 Markdown 在扫描期间变化也会令结果不完整。仓库发现使用 `scandir` 已返回的普通文件类型元数据，避免为不可能成为仓库的文件再次做路径查询；实际进入子目录前仍完整复核物理路径。非法编码、权限错误、同大小同 mtime 变化、晚出现目录项和特殊项都形成可见问题，不静默给出“完整”结果。关闭字符统计时仍生成全部文件画像，但不打开正文，也不使用跨轮元数据缓存冒充精确字符统计。

只读 I/O 使用 [reading.py](../../../obmanage/reading.py) 的大小自适应缓冲；镜像及部署的相邻文件祖先查询最多合并 16 项/250 ms，每个文件的身份/句柄校验和最终清单屏障仍执行。回收站安全子路径直接复用 paths 检查，避免重复物理路径解析。部署进度总字节在一轮复制前计算，避免逐文件遍历来源。完整对照见[性能验证](../../../docs/性能验证.md)。

## 限定子树部署

各页面使用[共享选择适配器](../../../obmanage/pages/vault_selection.py)，在全局单任务槽内提供列表、运行识别及浏览。运行识别通过 Windows 可见（含最小化）窗口的所属进程完整路径和标题核验，登记路径只用于唯一映射；单一结果填入，多结果选取，歧义与不可读可见。识别前后两次窗口观察不一致时拒绝旧结果。

“.comSync”使用[来源选择窗](../../../obmanage/pages/vault_chooser.py)按名称或完整路径搜索。`read_registered_vault_candidates` 读取全部登记项，使用 `discover_vaults(recursive=False)` 只校验这些精确根，再合并当前集合的递归发现结果；坏记录显式提示，合法候选仍可选择。`read_opened_vault_candidates` 继续只读取 `open: true`，供独立占用检查使用。显式搜索根处于 `.obmanage-deploy-*` 恢复目录内也会被拒绝，防止登记记录把内部副本带入来源列表。

五组件规则位于 [comsync.py](../../../obmanage/management/comsync.py)：前三种配置完整同步，Templater 对应 `File/Templater`；File 展开为同一份 Templater 与 Note/Attachment 两个空目录意图。已有目录只核验身份，不扫描其内容，不生成替换/删除或恢复清单；新目录使用已有同卷事务，撤销只接受仍匹配空目录快照的本次实体。

创建时间通过 collection 扫描或来源选择 worker 附加，根目录 birth time 不可读则显式提示。只有该页有最新按钮，排除来源并选择最大创建时间的全部并列候选，清空过滤和旧勾选；目标默认仍为空。

恢复按 [ADR-010](../../决策/ADR-010-事务结束与备份清理解耦.md) 将事务结束与副本删除分开：`resolved` 保留现状和全部副本，仅更新认证记录；恢复预览绑定修订和全内容快照，保全回退将当前内容存入认证 `.rollback` 路径，原备份完整验证后恢复。新增 `preserved_manifest` 兼容旧记录缺省字段，保全内容永不自动删除。已结束事务清理失败不重新阻塞，不能回退覆盖后续任务；全局门禁与部署引擎共用终态集合。

页面按来源、目标、预览三步呈现。目标筛选经代理模型映射回真实行，批量选择只添加可见候选；完整路径保留悬停及右键复制。恢复区位于独立“事务处理”页；无记录时隐藏，进入页面或切换事务后自动只读检查，详情按需展开。保留现状直接结束，删除和回退各只确认一次。待处理优先、保留历史持续可选，长路径可完整选取复制。

[`deployment.py`](../../../obmanage/management/deployment.py) 只接受显式组件、来源和目标。组件可表示根下固定子树或直接来源目录；目标必须是真实仓库，来源与目标、状态目录与仓库不得相同或包含，目标选择不得重复或互相包含。分析输出文件与目录的新增、更新、删除和跳过，目录结构变化不再被隐藏。

执行为“全目标准备屏障”：在每个目标所在卷创建应用自有暂存目录，经共享复制内核复制候选子树，再在准备阶段以一次完整暂存树 SHA-256 清单校验所有目标字节；不在紧邻整树校验前重复哈希每个暂存文件。全部准备成功后才依次进入提交，提交边界仍再次整体复核暂存树以发现并发变化，再用目录改名切换。旧目标保存在带身份锚点的 backup 中，失败按逆序恢复。持久 [`journal.py`](../../../obmanage/management/journal.py) 把来源、目标根、限定相对路径、卷身份和清单绑定到创建时授权；journal 损坏、密钥/授权不一致、未确认的目标变化或未知内容都会阻止自动改动；认证有效时用户可保留现状结束事务。部分 backup 清理只接受认证清单的严格剩余子集，可重试但不扩大删除范围。

部署页面执行前再次读取 Obsidian 当前打开仓库状态。明确打开的目标直接拒绝；配置不可可靠读取时必须额外确认已关闭所选目标。目标永远默认不选，切换来源、组件或目标会使预览与确认失效。

## 回收站直接清理

[`trash.py`](../../../obmanage/management/trash.py) 只处理发现结果中每个仓库的根级 `.trash`。分析稳定扫描并生成带完整内容摘要的精确清单，且零写入。页面载入扫描结果时默认勾选全部非空项，空项不可勾选；路径复制入口已移除，不可恢复确认仍默认关闭，选择、路径或页面上下文改变会撤销确认。

新执行不创建隔离目录、journal 或认证密钥。取得进程内及状态目录跨进程锁后，服务先重扫所有所选仓库；任一签名变化即在删除前拒绝整批。随后每个仓库再次重扫，并只按原预览快照逐项删除，保留 `.trash` 根；执行期间新出现的项目不获得删除授权。取消、权限或结构性复核失败可能形成不可恢复的部分结果，返回值保留已删除文件、目录和逻辑字节计数，页面使旧计划失效并要求重新扫描。

已存在的隔离 journal、HMAC 和副本仍由 `list_operations`、`restore` 兼容读取和恢复，统一在“事务处理”列表管理。`clear_transaction` 持有同一进程锁与跨进程锁，先 `_finalize_locked` 验证并清除全部副本，再移除完成记录；失败保留记录，已完成副本的历史记录也走同一入口。枚举审计 journal 全部条目及备份根 UUID；未知临时记录、非法目录或缺少 journal 的孤立备份均 fail closed。待处理批次或认证失败继续阻止新的直接清理。程序不自动清除副本。

## ZIP 归档与可筛选日志

[归档服务](../../../obmanage/management/archive.py) 只读扫描来源并生成含 SHA-256 的目录/文件清单；支持单个仓库或集合、同一视频扩展名过滤、0–9 ZIP 压缩级别及空目录。目标不是镜像目录，而是一个不存在的 ZIP 文件；可以选来源上级目录，但不能将输出放入来源内。输出同卷创建独占临时句柄，流式压缩并完整读取 ZIP 验证，然后重读来源及最终清单/卷身份，最后不覆盖地发布。失败或取消只清理本次身份匹配的临时包，强停残留不猜测删除。Windows 路径与句柄 ctime 语义不同，跨 API 比较共同的设备/文件 ID/大小/mtime，各 API 内的前后 ctime 和完整内容哈希继续保留。

[归档页](../../../obmanage/pages/archive.py) 通过现有 FeatureWorker 运行；新写入同样受[恢复门禁](../../../obmanage/management/recovery.py)保护。保存位置有自选/百度同步两个可记忆配置，客户端仅成功后按用户选项调用，不读取凭据，不推断上传完成。覆盖测试见[归档服务测试](../../../tests/test_archive.py)与[工作台流程测试](../../../tests/test_archive_page.py)。

[日志服务](../../../obmanage/operation_log.py)用 JSONL 保存功能、事件、任务、状态和消息，并保留纯文本兼容副本。界面读全部保留历史再组合筛选，兼容副本按数量去重，多行错误保持为一条记录。新任务 ID 不随切页变化；无标签旧记录保留在“历史日志”，不推测其功能。轮转为当前文件加四份约 2 MB 历史；展示最多 2,000 条时明确提示，复制全部匹配记录。损坏/不可读条目以问题列表呈现。验证见[日志测试](../../../tests/test_operation_log.py)。

## 页面、任务和恢复门禁

[`ui.py`](../../../obmanage/ui.py) 保留镜像 `SyncWorker(QThread)` 生命周期，其他页面经 [`tasking.py`](../../../obmanage/tasking.py) 的通用 worker 使用同一个应用任务槽。页面可在任务运行时切换，真正支持取消的操作才显示全局取消；定时到点若忙碌或存在待恢复事务会消费并跳过，不排队补跑。

部署或升级前遗留隔离记录处于待处理状态，或任一记录无法安全枚举时，恢复门禁禁用所有新写入。统一分发页处理全部部署标签的撤销和确认，回收站页处理对应遗留恢复；统计等只读能力不改变事务状态。多个待处理批次必须可选择，不能让较新的失败批次遮住较旧批次；未知或旧版本 label 的合法部署批次全部由 .comSync 页作为统一恢复入口。新的回收站直接清理不会产生恢复门禁。

程序数据目录与任一镜像、集合根或来源相等/包含时，CLI 和 GUI 都在日志、设置、锁或任务写入前拒绝。服务层仍重复检查，不能只依赖按钮状态或启动参数。

## 常见问题或陷阱

- HMAC 证明记录与本应用密钥一致，不证明同账户恶意进程未同时替换密钥、记录和仓库；不要把它描述为权限隔离。
- 部署和遗留隔离的 `finalize` 是不可逆释放恢复副本，页面必须单独确认，且取消只在底层实际检查取消事件时显示。
- 回收站直接清理本身不可撤销；不能把逻辑删除字节描述成文件系统保证的实际可用空间增量，也不能在部分失败时丢失已删除计数。
- 发现 `.obmanage-deploy-*` 时不要按普通仓库内容复制、统计或删除；它可能是唯一可撤销原件。
- 真实仓库只做用户明确触发的只读预览；故障执行测试全部使用隔离临时目录。
