# 仓库管理服务与事务

## 一句话结论

非镜像页面的 Qt 代码只编排输入、预览、确认和恢复；仓库发现、统计、限定子树部署与回收站隔离均位于无 Qt 依赖的 [`management`](../../../obmanage/management/__init__.py) 服务层，并通过临时目录故障测试验证。

## 仓库发现与统计

[`catalog.py`](../../../obmanage/management/catalog.py) 只把带普通 `.obsidian` 目录的路径认作仓库，按物理身份去重，拒绝链接、重解析点和不可安全读取的边界。父仓库下的嵌套仓库作为独立仓库，不重复穿透统计；父仓库根级 `.trash` 视为已删除内容，里面残留的 `.obsidian` 不会成为统计或分发目标。应用自有 `.obmanage-deploy-*` 恢复目录是保留命名空间，发现、统计和镜像均不进入。

[`statistics.py`](../../../obmanage/management/statistics.py) 始终排除根级 `.obsidian`，默认排除根级 `.trash`，只统计普通 Markdown 文件。字符数按严格 UTF-8 码点流式读取；文件句柄与当前路径会复核身份、大小、时间 epoch，每个遍历目录在内容读取后再做稳定枚举。非法编码、权限错误、同大小同 mtime 变化、晚出现目录项和特殊项都形成可见问题，不静默给出“完整”结果。关闭字符统计时只读元数据，不打开正文。

## 限定子树部署

[`deployment.py`](../../../obmanage/management/deployment.py) 只接受显式组件、来源和目标。组件可表示根下固定子树或直接来源目录；目标必须是真实仓库，来源与目标、状态目录与仓库不得相同或包含，目标选择不得重复或互相包含。分析输出文件与目录的新增、更新、删除和跳过，目录结构变化不再被隐藏。

执行为“全目标准备屏障”：在每个目标所在卷创建应用自有暂存目录，复制并 SHA-256 校验完整候选子树；全部准备成功后才依次用目录改名提交。旧目标保存在带身份锚点的 backup 中，失败按逆序恢复。持久 [`journal.py`](../../../obmanage/management/journal.py) 把来源、目标根、限定相对路径、卷身份和清单绑定到创建时授权；journal 损坏、密钥/授权不一致、目标变化或未知内容都会 fail closed。部分 backup 清理只接受认证清单的严格剩余子集，可重试但不扩大删除范围。

部署页面执行前再次读取 Obsidian 当前打开仓库状态。明确打开的目标直接拒绝；配置不可可靠读取时必须额外确认已关闭所选目标。目标永远默认不选，切换来源、组件或目标会使预览与确认失效。

## 回收站隔离

[`trash.py`](../../../obmanage/management/trash.py) 只处理发现结果中每个仓库的根级 `.trash`。分析稳定扫描并生成精确清单；执行先在应用状态目录为操作和每个仓库独占创建身份锚点，再复制、同步、重新扫描和校验隔离副本，journal 成功落盘后才逐项删除仓库预览内容，保留 `.trash` 根。

恢复只写回身份未变且仍为空的原 `.trash`；永久清理需要再次确认。隔离清理发现未登记项或内容改变时，在删除前拒绝；中途中断后只允许清理原认证清单的完整或严格剩余子集，并按原总量减认证剩余量累计实际释放空间。全部仓库记录 finalized 后，操作根只有在身份匹配且为空时才删除。

## 页面、任务和恢复门禁

[`ui.py`](../../../obmanage/ui.py) 保留镜像 `SyncWorker(QThread)` 生命周期，其他页面经 [`tasking.py`](../../../obmanage/tasking.py) 的通用 worker 使用同一个应用任务槽。页面可在任务运行时切换，真正支持取消的操作才显示全局取消；定时到点若忙碌或存在待恢复事务会消费并跳过，不排队补跑。

部署或隔离记录处于待处理状态，或任一记录无法安全枚举时，恢复门禁禁用所有新写入。每页只允许处理自己的撤销、恢复或最终确认；统计等只读能力不改变事务状态。多个待处理批次必须可选择，不能让较新的失败批次遮住较旧批次；未知或旧版本 label 的合法部署批次由配置分发页作为兼容恢复入口兜底。

程序数据目录与任一镜像、集合根或来源相等/包含时，CLI 和 GUI 都在日志、设置、锁或任务写入前拒绝。服务层仍重复检查，不能只依赖按钮状态或启动参数。

## 常见问题或陷阱

- HMAC 证明记录与本应用密钥一致，不证明同账户恶意进程未同时替换密钥、记录和仓库；不要把它描述为权限隔离。
- `finalize` 是不可逆释放恢复副本，页面必须单独确认，且取消只在底层实际检查取消事件时显示。
- 发现 `.obmanage-deploy-*` 时不要按普通仓库内容复制、统计或删除；它可能是唯一可撤销原件。
- 真实仓库只做用户明确触发的只读预览；故障执行测试全部使用隔离临时目录。
