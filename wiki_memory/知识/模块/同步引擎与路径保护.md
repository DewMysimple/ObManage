# 同步引擎与路径保护

## 接口与计划

`SyncEngine(state_dir).analyze(source, target, deep=False, mode="mirror", cancel=Event, progress=callback)` 返回 `SyncPlan`。错误追加到 `errors` / error 项，取消抛出 `SyncCancelled`；只有完整扫描及结束复核后 context 才标为 validated。`execute(plan, allow_empty=False, ...)` 返回 success / failed / cancelled 的 `SyncResult`，保留已经完成数量。`mode="no_video"` 使用相同安全执行流程，但从两端管理清单排除共享视频扩展名。

计划包括 source/target/pair_id、所有普通文件和目录的元数据快照、目标实际大小写名称、根/卷/锚点身份。不能自行拼装 PlanItem 列表绕过 context，也不能在预览后直接修改其中路径执行。

无视频计划另绑定 mode、基础 pair identity 和 profile pair identity，并记录两端排除文件数量/字节。排除路径用 `exclude` 项显示但不计入 `has_changes`：来源视频不哈希或复制，目标视频不覆盖或删除；目标视频的所有祖先目录进入删除保护集合。完整镜像保留旧 pair key 兼容，无视频 profile 使用独立命名空间，反向记录也只在相同 profile 内复用。

## 文件处理

- 清单屏障失败用已经读取的预览/当前快照生成诊断，不重扫、不刷新授权。报告端点根、变化数量、最多 8 个路径及字段前后值，超出项数显式提示；只描述元数据和路径变化，不推断正文或写入者。增量批量预复核附加仓库名，完整错误保存在本地操作日志与 UI 悬停。
- 同名同大小未被缓存确认的文件做 SHA-256；大小不同直接计划更新。已有相同目录不计入跳过文件数。
- 深度校验先用一个 SQLite 事务退役当前和反向方向的旧等价记录，再重新读取两端。不同卷对同一文件用固定两个 worker 并行哈希，同卷顺序读取；公开进度只从分析线程发出，任一端失败或取消会汇合全部 worker，随后再次复核双端快照。
- 大小写改名有单独 `rename`，目录先于子项处理；普通重命名是新增路径加删除旧路径。exFAT 可成功返回但未改变大小写，需枚举验证实际名称后再使用唯一同级临时名称两步改名；临时名不长于原名，避免 exFAT 目录项搬迁导致文件 ID 变化。两步间不响应取消，失败尽力恢复原名，不覆盖其他程序新建项、不猜测删除残留；身份检查不放宽。
- `analyze_pair` 仅对两个已存在的完整镜像根使用：一次比较及最终清单屏障生成两份独立方向计划，复用相等和不等结论，反向不扫描、不哈希。反向复制大小及路径来自反向来源清单，执行时仍完整预复核。哈希读取块大小按文件大小上限分配，避免小文件每次分配 4 MiB。
- 复制经 [`copying.py`](../../../obmanage/copying.py) 使用最多 4 MiB 的大小感知复用缓冲区，在一次来源读取中处理短写并计算 SHA-256。接收方同目录随机临时文件仍登记精确所有权；关闭写句柄后重新读取临时文件核对 SHA-256，设置时间后 `os.replace`。不再为每个文件调用 `FlushFileBuffers`，但完整写后读取校验不变，目标内容在完整临时副本就绪前不会被截断。异卷时一个专用 worker 最多提前写下一临时文件，主线程同时校验当前临时文件；同卷保持串行。任一异常都会先汇合 worker，再按登记身份清理尚未提交的临时项。
- `os.replace` 后通常以暂存态和最终态的文件身份、大小及时间做快速复核。exFAT 可能在改名时重发文件 ID；若最终目标仍是预期大小的普通文件，但身份或时间变化，则必须对最终路径再做一次稳定 SHA-256，内容一致才接受并保存最终实际快照。
- Windows 的目标普通文件若带 `ReadOnly`，`os.unlink` 会返回 WinError 5，部分文件系统上的 `os.replace` 会返回 WinError 5 或 183。引擎只在该错误、目标仍精确匹配预览、确认只读且硬链接计数为一时清除此位，清除前后再次核对身份与完整文件元数据再重试；二次失败只在同一快照仍保持单硬链接时尽力恢复只读位。普通权限错误和多硬链接不重试，不处理来源或目录属性。
- 复制前后复核来源及目标；相邻调用可复用同一次安全子路径检查返回的快照，但不会跳过祖先链或文件身份比较。完整卷/根/锚点复核最多间隔 16 个文件或 250 ms，长文件替换前及写入、删除、完成屏障强制复核。正常删除前重新扫描来源并验证预期目标，再逐一核对目标文件和来源不存在；删除后再次完整复核。没有删除项时，复制后的来源与预期目标完整复核已经是最终状态，省略其后没有任何文件系统写入的重复一轮。目录只用 `rmdir` 删除空目录，不递归删除未经检查内容。
- 无视频目标的保留目录判断沿当前相对路径祖先查找受保护集合，复杂度随路径深度增长，不再让每个非视频文件遍历全部视频目录；保护集合与大小写语义不变。
- 崩溃临时文件回收必须匹配 SQLite 的精确路径和身份，不能按 `.obmanage-*` 通配删除。
- 视频判断集中在 [`file_types.py`](../../../obmanage/file_types.py)，统计与过滤共用一个大小写不敏感集合；`.ts` 不属于视频集合，未知扩展名仍按普通文件管理。

## 路径与状态

Windows 文件访问统一经 `native()` 扩展路径。`validate_roots()` 先拒绝链接祖先，再规范真实路径以处理 8.3 别名，检查相同/包含/盘根；`checked_child()` 拒绝 `..`、绝对逸出和重解析点。根身份与磁盘身份在执行期间多次复核。

SQLite 使用 WAL，等价记录逐文件提交并在工作线程内创建和关闭连接；状态目录不能落在任何同步根内。记录表保持旧五列兼容，Windows 大小写等价路径在单事务中归并，`data_version` 会使陈旧连接写入失败。GUI、CLI 预览和同进程引擎共享单任务边界。预览阶段允许写外部状态，不允许创建缺失的目标根或修改仓库。
