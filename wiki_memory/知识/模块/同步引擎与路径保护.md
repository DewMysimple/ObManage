# 同步引擎与路径保护

## 接口与计划

`SyncEngine(state_dir).analyze(source, target, deep=False, cancel=Event, progress=callback)` 返回 `SyncPlan`。错误追加到 `errors` / error 项，取消抛出 `SyncCancelled`；只有完整扫描及结束复核后 context 才标为 validated。`execute(plan, allow_empty=False, ...)` 返回 success / failed / cancelled 的 `SyncResult`，保留已经完成数量。

计划包括 source/target/pair_id、所有普通文件和目录的元数据快照、目标实际大小写名称、根/卷/锚点身份。不能自行拼装 PlanItem 列表绕过 context，也不能在预览后直接修改其中路径执行。

## 文件处理

- 同名同大小未被缓存确认的文件做 SHA-256；大小不同直接计划更新。已有相同目录不计入跳过文件数。
- 大小写改名有单独 `rename`，目录先于子项处理；普通重命名是新增路径加删除旧路径。
- 复制用 4 MiB 块，写接收方同目录随机临时文件，记录所有权，flush/fsync，再读临时文件核对 SHA-256，设置时间后 `os.replace`。目标内容在完整临时副本就绪前不会被截断。
- `os.replace` 后通常以暂存态和最终态的文件身份、大小及时间做快速复核。exFAT 可能在改名时重发文件 ID；若最终目标仍是预期大小的普通文件，但身份或时间变化，则必须对最终路径再做一次稳定 SHA-256，内容一致才接受并保存最终实际快照。
- 复制前后复核来源及目标；正常删除前重新扫描来源并验证预期目标，再逐一核对目标文件和来源不存在。目录只用 `rmdir` 删除空目录，不递归删除未经检查内容。
- 崩溃临时文件回收必须匹配 SQLite 的精确路径和身份，不能按 `.obmanage-*` 通配删除。

## 路径与状态

Windows 文件访问统一经 `native()` 扩展路径。`validate_roots()` 先拒绝链接祖先，再规范真实路径以处理 8.3 别名，检查相同/包含/盘根；`checked_child()` 拒绝 `..`、绝对逸出和重解析点。根身份与磁盘身份在执行期间多次复核。

SQLite 使用 WAL，等价记录逐文件提交并在工作线程内创建和关闭连接；状态目录不能落在任何同步根内。预览阶段允许写外部状态，不允许创建缺失的目标根或修改仓库。
