# 开发验证与交付

## 工作顺序

先读根协作指令与[记忆协议](../../AGENTS.md)，核对 `git status --short` 和本轮涉及源码。已有用户修改保留；并行工作按文件边界分工，不能重置其他人的未提交更改。

按相关层验证：引擎改动用临时目录及故障注入；方向和状态变化测 UI；排版同时检查窗口及最大化实际截图；打包变化必须跑 EXE。UI 调整后要确认读写方向、确认勾选、目标路径和任务互斥没有被排版改坏。

## 可重复命令

从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe wiki_memory\工具\memory_lint.py index
.\.venv\Scripts\python.exe wiki_memory\工具\memory_lint.py check
.\.venv\Scripts\python.exe wiki_memory\工具\test_memory_lint.py
.\.venv\Scripts\python.exe tools\render_demo.py
.\.venv\Scripts\python.exe tools\render_demo.py --maximized --output artifacts\ui-maximized.png
.\.venv\Scripts\python.exe tools\build.py
```

[pytest.ini](../../../pytest.ini)默认只收集 `tests/`，记忆工具的标准库测试需单独执行。只修改文字不必写镜像实现式测试；修改 lint 时用 fixture 验证真实失效条件。

## 产品验收范围

[引擎测试](../../../tests/test_engine.py)覆盖新增/修改/删除/目录/重命名/隐藏文件、二次零字节、初次接管、时间差、深度检查、取消及多类失败。[路径测试](../../../tests/test_paths.py)覆盖长中文路径、包含关系、链接与 8.3 别名。[往返测试](../../../tests/test_roundtrip.py)包括两个方向的来源写操作拦截、内容及身份保持。[UI 测试](../../../tests/test_ui.py)与[方向测试](../../../tests/test_direction_ui.py)验证完整操作和定时交互。

GUI 异步测试使用事件处理配合短 `time.sleep` 等待真实状态，避免仅依赖连续 Qt wait 阻碍 Python worker 获得执行机会。等待必须有超时，不能靠固定睡眠假定完成。

[布局回归](../../../tests/test_ui_layout.py)另检查四列、右边缘填满、无水平滚动、长路径完整复制及可见列分隔。用[render_demo.py](../../../tools/render_demo.py)生成无私人数据的真实 Qt 截图；默认输出供 README 使用的[界面示例](../../../docs/images/main-window.png)，不扫描或执行实际仓库。验证最大化时使用 `--maximized`，不是仅 resize 为屏幕尺寸；脚本在原生窗口创建后再次请求最大化，避免 Windows 首次 show 服从启动参数。

每次完整对话产生实质修改都要在最终源码上运行打包，生成 `dist/ObManage/` 和根目录平铺的 `dist/ObManage.zip`；解压 ZIP 后直接就是程序根目录。打包会把[独立使用指南](../../../docs/使用指南.md)复制为便携包的使用说明。README 服务 GitHub 读者，可以链接源码和示例图；便携指南须在离开仓库后仍可独立阅读。

真实仓库只读验收使用 `--preview`，测试状态放隔离目录；输出含私有路径和文件名，不进 Git。不能把一次无副作用预览当作真实执行验证。

## 对话交付

补齐工作日志的实际测试结果与局限，清理当前待办，刷新索引并检查 diff。按用户明确要求提交本轮相关文件并推送当前分支，核对本地 HEAD 与远端分支；最终告知真实结果。推送失败不能宣称交付完成，也不能强制覆盖远端。提交/推送验证详见[ADR-004](../../决策/ADR-004-工程记忆与每轮交付.md)。
