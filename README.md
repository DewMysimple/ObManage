# ObManage · 往返镜像

一个中文 Windows 桌面程序，用于本机与移动硬盘之间往返携带 Obsidian 仓库。每次明确选择同步方向，以所选来源的状态为准，只修改另一边；新增、修改和删除都会同步，未变化文件跳过复制。

## 打开程序

打开便携程序目录中的 **ObManage.exe**。请保留旁边的 `_internal` 文件夹；可以移动整个程序目录，无须安装 Python。

界面固定显示两处位置：**本机仓库**（主机或笔记本）与**移动硬盘仓库**。默认分别为当前用户桌面上的 `Obsidian仓库` 和 `H:\ObsidianVault\Obsidian仓库`。两个路径都能修改，切换同步方向不会交换这两行的位置。选择的文件夹就是最终仓库根目录，不会再套一层。

## 日常使用

1. 确认本机和移动硬盘的仓库路径。
2. 选择 **带走到移动硬盘：本机 → 移动硬盘**，或 **带回本机：移动硬盘 → 本机**。
3. 检查方向提示中的“本次以此为准”和“本次仅修改这里”，点击 **分析差异**。
4. 预览默认显示待执行变化，操作名称与实际修改位置明确指出接收改动的一边。未变化文件可以切换到“跳过”查看。
5. 勾选本轮方向确认，然后点击 **更新本机** 或 **更新移动硬盘**。执行时可查看进度、当前文件、速度与结果，也可以取消。

| 选择的方向 | 本次以谁为准 | 新增、覆盖、删除发生在哪里 |
| --- | --- | --- |
| 本机 → 移动硬盘（例如 C → H） | 本机仓库 | 仅移动硬盘仓库 |
| 移动硬盘 → 本机（例如 H → C） | 移动硬盘仓库 | 仅本机仓库 |

例如选择 **H → C** 时，H 中已删除但 C 还存在的文件，会从 C 删除；H 中新增的文件会复制到 C。程序不会覆盖或删除 H 中的来源文件。接收方单独添加的内容也会按来源状态清理，接收方较新的修改不会自动优先。

常用流程是：主机工作结束后带走到移动硬盘；到笔记本先带回本机；笔记本工作结束后再次带走到移动硬盘；回主机后带回本机。如果直接在移动硬盘仓库中工作，回主机后选择 H → C 即可。每次选择当前工作成果所在的一边作为来源，程序不合并两边各自独立的修改。

首次接管已有副本时，程序会读取同大小文件进行 SHA-256 内容比较。内容相同就建立记录、跳过复制，即使 NTFS 与 exFAT 的时间戳不同。首次校验可能较慢，读取校验不等于重新复制；取消后可复用已完成的校验记录。

后续运行分别检查两边与上次记录的大小和精确修改时间，未变化的大文件不会再次读取内容。往返切换方向时，可复用两端版本均未改变的已校验记录。**完整内容校验**会重新读取内容、生成差异预览，用于发现内容已变但大小和修改时间均未变的情况；校验后仍需确认方向并点击更新按钮才会修改接收方。

取消或失败时，结果会显示已完成和未完成的部分。已完成文件不回滚；未完成的普通文件先写临时文件，成功后才替换旧文件。再次分析并同步即可继续。新增、更新失败时不再进行后续删除。文件与目录同名的冲突需要先手动处理后重新分析。

## 定时与托盘

默认关闭定时。可以开启“每隔若干分钟”或“每天指定时间”，使用电脑当前本地时间。

- 开启定时后，关闭主窗口会留在右下角系统托盘，继续按时同步。
- 托盘可以打开窗口、立即分析同步、暂停定时或退出。
- 明确选择退出会停止后台定时；本版本不安装 Windows 服务或开机启动项。
- 一次只执行一个任务。运行中不能切换路径，到点时若已有任务就跳过本次，不累计补跑。
- 切换方向或修改任一仓库路径，会清除旧预览与确认勾选并暂停定时，需要重新开启以绑定当前方向。升级旧版设置后也需重新开启定时。
- 磁盘未连接时跳过本次，下一次到点再检查。空源需要清空目标时，定时暂停，需在主窗口手动确认。

## 同步范围

包含隐藏文件、Obsidian 配置、空文件夹和所有普通子目录。支持中文及 Windows 长路径。目录链接、符号链接和其他重解析点会明确报错，不跟随链接访问范围之外的数据。

这是普通文件内容及目录结构的镜像，目标可直接浏览、打开。文件发生内容变化时按整个文件复制，一般重命名按新路径复制、旧路径删除处理；仅大小写变化时直接改名，不重拷内容。不进行视频内部的分块复制，也不复制 NTFS 权限、备用数据流或历史版本。

运行时源文件若仍在变化，程序会检查并报告不稳定文件，避免把这一轮误报为完整成功。源文件夹不存在、扫描失败、磁盘身份变化或路径范围不正确时会停止操作。

## 设置与日志

设置、SQLite 同步记录和轮换日志存放于 `%LOCALAPPDATA%\ObManage`，不会写进你的来源仓库或镜像内容中。界面提供本次任务日志，`obmanage.log` 保存持久运行记录。两个方向分别保存有序路径与磁盘身份，避免把上次的方向误用到本次操作。

## 从源码运行与构建

需要普通 GIL 版 Python 3.14 x64，在项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m obmanage
```

测试及打包：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe tools\build.py
```

产物位于 `dist\ObManage\ObManage.exe`。构建目录以 `onedir` 形式保留动态 Qt 库，未请求管理员权限，EXE 声明支持长路径和高 DPI。

只读预览命令（会更新本机校验记录，但不写入源或目标）：

```powershell
.\.venv\Scripts\python.exe -m obmanage --preview --source 'H:\ObsidianVault\Obsidian仓库' --target 'C:\Users\Administrator\Desktop\Obsidian仓库'
```

加 `--deep` 可强制完整校验，加 `--state-dir` 可将测试记录隔离到指定目录。命令行只提供预览，不提供直接删除或执行镜像的入口。
